# 從問題與直覺走到數學的學術教學

讓讀者知道「為什麼現在需要這個數學物件」，再理解它如何解決問題。精簡的是重複與修辭，不是推理所需的中間步驟。這套方法適用於理論筆記與課程正文；不規定實作章節、程式架構或投影片製作方式。

## 開始前

- 先讀適用的 repository instructions、作者的書寫 guide、待改篇章，以及必要的前後篇。作者提供的替換文字優先；只有明確的數學、術語、格式或交叉引用錯誤需要更正並說明。
- 整理三件事：讀者已經知道什麼、目前還不能解決什麼、這一篇結束時應該能說清楚什麼。不要為了完整介紹一個領域，塞入與這個問題無關的內容。
- 沒有其他設定時，預設讀者是一般資工系學生：接觸過微積分、向量、基礎機率與 regression，但未必知道進階 ODE、測度論、optimal transport 或論文慣用術語。用當前課程已教過的內容校正這個預設。
- 列出沿用的符號、時間方向與已定義術語。以課程符號為準，不直接搬入論文的另一套 notation。

## 主線：讓下一步有必要

以下是因果順序，不是每篇都要套用的固定小標。

1. **從手上已經有的結果出發。** 用一兩句回顧足以支持新問題的內容，隨即指出具體缺口：不知道終點、只能走相鄰一步、平均後是否還保留 distribution、或有限步近似漏掉了什麼。
2. **提出讀者可能自己想到的做法。** 問題要由缺口產生，不是先公布方法，再補一句「為什麼」。不要假裝讀者已經想到尚未介紹的答案。
3. **用生活經驗或簡單直覺找出一個動作。** 例如參考同一街口的人、比較走道兩端的人流、試走一步再查方向。這個動作必須能帶出下一個數學操作，而不只是替公式換個比喻。
4. **把動作寫成數學物件，講清楚對應。** 哪個量代表位置、速度、密度、標籤或未知來源？我們知道什麼、要估計什麼、哪些限制不能改？先回答這些問題，再命名方法。
5. **操作這個物件，檢查做法是否真的有效。** 展開、代入、條件平均、比較或做局部近似；每個關鍵變形都有理由。定理不能代替這段理解。
6. **回到原問題，說出得到的 insight 與界線。** 哪件事解決了？是等式、上界、有限條件下的保證，還是實驗觀察？剩下的哪個缺口需要下一篇？

已有熟悉的數學物件時，可以直接用它，不必強行新增故事。新方法的邏輯推演可以模仿研究發展的思路，但沒有來源時，不聲稱這就是作者當年的歷史動機。

## 生活例子：出現在需要它的地方

- 在讀者不容易自己想到「下一個動作」時使用例子，通常放在新數學物件之前；推導後用一句話回到原例子，確認數學說了什麼。
- 選可能親身經歷的情境，交代角色、可見資訊與要做的決定。優先延續已建立的例子，不每段換一個世界。
- 只保留支撐機制的細節。迷路者不知道目的地，才需要在當下位置參考人潮；不能一邊說他不知道終點，一邊讓他沿已知終點的直線走。
- 比喻的對應必須精確。人潮的「擁擠程度」對應 density，「每秒通過多少人」還要乘上速度；score 是當下的局部梯度，不是完整生成路線。
- 簡單 toy example 要真的展示所聲稱的現象。在一個交叉點算出平均箭頭，不足以證明 ODE trajectory 會彎；還要說明沿途的平均方向如何改變。
- 不把日常經驗當成證明。直覺提出做法，數學檢查做法，兩者各自完成任務。

## 新概念與符號：先有角色，再有名字

每個新概念至少交代：**描述什麼、為何需要、如何定義、怎麼讀這個定義。** 可用一句短句總結，再給嚴謹版本。

- 新 expectation 要交代對哪些隨機量平均、固定了什麼條件、平均的 label 是什麼。不要只說「取平均」。
- 新誤差或 variance 要交代比較對象、平均範圍，以及零與變大的意義。避免把不同量都叫「彎」或「誤差」。
- 寫明資料、訓練與生成各自能取得的資訊。推導時可以條件化已知端點，不表示生成時也知道它。
- 維持角色一致：random variable、一次 realization、reference process、ideal field、learned field、精確生成 trajectory 與 discretized samples 不互相代用。
- DMA 的既有範例是 $I_t$ 表示 reference process、$v_t$ 表示 ideal velocity、$v_\theta$ 表示模型；$Z^{(k)}$ 表示 reflow 輪次、$a_t$ 表示 acceleration。其他課程沿用自身的角色表，不強制照搬。
- 若時間方向或參數意義改變，當場對照。例如 signal amplitude 和單步保留率不是同一個量；不要讓讀者靠下標猜。
- 專有名詞給自然的中文說明並保留必要英文。不要提前使用尚未介紹的 OT、coupling、simulation-free 或 NFE。

## 推導：每一個重要等號都有機制

- 推導前寫出起點、想得到的式子與必要假設。只有在理想 velocity、精確 ODE 或特定正則性下成立的結果，要在使用時說明。
- 一個重要變形處理一個機制。代入從哪裡來？交叉項為何為零？為何可以換成另一個 process？使用哪個不等式？不要連寫數行後才籠統說「整理可得」。
- 先給具體、可追蹤的一步，再推廣。局部 error 變成終點 error 前，先相減兩個更新式、取 norm、用三角不等式，再用 Lipschitz 控制速度差，最後展開遞迴。
- 名稱不能跳過說明。用 Jensen 時說明平均的是時間還是條件分布；用 law of total variance 時指出保留項與漏掉項；用 Lipschitz 時說明 input 距離如何控制 output 距離。
- 高維、抽象結果若可由一維或少量點看清楚，先做小例子。數值與符號必須一致，例子不能偷偷滿足一般情況沒有的特殊條件。
- 說清楚精確項、近似項、remainder 與階數，以及局部和全域誤差的差別。比較 solver 時，區分步數和 network evaluations；不要把高階直接等同於所有設定都更好。
- 主線保留關鍵推理與 insight。重複證明、額外條件、一般化或技術細節可收進原站的補充 block；不能把理解正文必需的定義與中間步藏起來。
- 已證過的機制優先引用並解釋如何套用。只有新假設改變適用範圍，或這一篇需要新的理解方式時，才重做證明。

## 保證的範圍：相近但不同的量要分開

對照定義與推導檢查 claim，不靠敘事的順暢程度判斷它成立。

- 同一組 marginals 不表示同一個 joint、配對或 sample trajectory。
- 直線 reference paths 不表示平均 field 的 ODE trajectories 也是直線。
- Acceleration 衡量 velocity 隨時間的變化，包含沿直線加減速；curvature 是方向隨弧長的變化，不能直接互換。
- 成本逐輪不增加、成本下降量逐輪不增加、variance 逐輪不增加，是三個不同的命題。Reflow 的 $C^{(k)}-C^{(k+1)}=V+S\ge0$ 保證第一個，不直接保證後兩個。
- 前若干輪的最好值、最後一輪的值、漸近收斂與逐輪單調下降不是同一種保證。漸近趨近零也不自動等於達到某個全域最佳配對。
- Training objective 的理想解、neural model 的逼近誤差與 sampler 的 discretization error 分別處理。不要把理想定理說成實際訓練必然重現的效果。
- 繞過一個量，不表示已經算出它。Score 繞過 normalizing constant，不等於拿到 density 或 likelihood。

結果若只給出上界，使用「控制」「不超過」「在這些假設下」；不要改寫成必要條件、等價或逐項改善。若不知道是否有更強結果，先查原始論文；使用者要求後續研究時，再查後續主張與條件。

## 語氣、篇幅與段落節奏

- 使用繁體中文，以「我們已知什麼，因此現在可以試什麼」的共同推理口吻前進。保留自然的 technical English，但句子的因果關係用中文講清楚。
- 一段通常承載一個邏輯動作，約二至四句；這是節奏參考，不是字數限制。不要每句換行，也不要把數句必要推理擠成一個結論。
- 公式前說明為什麼要寫，公式後說明它說了什麼或接下來能做什麼。定義明確的短符號可用 inline math；公式的每個字母不必各占一行。
- 粗體只標主要問題與必要結論，不整段加粗。不用過多破折號、驚嘆語或刻意三段式口號。
- 標題指出目前要解決的問題或操作，例如「Euler 一步漏掉了什麼？」；不要只列抽象名詞，也不要在提出問題前就偷藏答案。
- 避免作者已排除的說法：「旋鈕」「套餐」「不負責」「先直接跑起來」「只有一個檔案」「解得漂亮，也綁得很緊」，以及空泛的「值得停一下」「名字有了，但問題還沒真正解決」。用具體因果取代口吻修飾。
- 精簡時先刪重複 recap、無作用的補充、連續反問與提前介紹；不先刪定義、對應或關鍵中間步。
- 修改時替換舊段落，不附加一段意思相同的新版。保留作者已確定的內容與站內元件。

## Objectives、提問與前後篇銜接

- **Objective：** 用讀者能檢查的動作描述核心理解，例如寫出 reference path 與其速度、指出平均的條件、推導誤差遞迴、分清兩個保證。避免只寫「了解／掌握某某方法」，也不要預告正文沒有教的能力。
- **課堂提問：** 放在讀者已有足夠材料、但可能作出一個合理錯誤推論的位置。答案指出錯在什麼假設或漏了哪一項，必要時算給他看；不以「以上皆是」代替推理。
- **補充：** 收納嚴謹定義、條件、重複證明或延伸結果，並保留一句對主線的意義。若正文馬上要用到概念，正文仍須交代它的角色。
- **Bridge：** 先用一句回答本篇原問題，再提出一個由結果產生、尚未解決的缺口。說明下一篇為何有必要，不列一串方法名稱，不使用尚未教的術語解釋另一個新術語。
- **方法來源：** 首次介紹研究方法時，自然交代提出者並引用原始來源，例如「Liu、Gong 與 Liu 把這個運算稱為 rectification」。定理與後續強化結果附對應來源，說明假設；作者名字不能取代推導。

## 操作流程與完成檢查

先用短綱要標出「已知 → 缺口 → 直覺動作 → 數學對應 → 檢查 → insight → 下一個缺口」，再改正文。使用者已批准改寫時直接落實，不多加一輪確認；缺少會改變主題的選擇時才詢問。

遇到轉場、新量或推導不夠清楚時，完整閱讀 [teaching-patterns.md](references/teaching-patterns.md) 的範例，再選符合當前問題的機制；不要機械複製句型。

交付前逐項檢查：

1. 開頭的問題能從前一篇的結果自然提出嗎？
2. 每個新物件出現時，讀者知道為什麼需要它嗎？
3. 生活例子真的支撐下一個操作，資訊與數量的對應都正確嗎？
4. 隨機量、條件、時間方向與沿用符號能不靠猜測辨認嗎？
5. 每個關鍵等號、不等號都有可追蹤的理由嗎？
6. 新量和前文相近的量有分清楚嗎？
7. 假設、近似與 claim 的保證範圍一致嗎？
8. 主線、補充、objective、提問與 bridge 是否講同一件事？
9. 刪掉重複後，是否仍保留一般資工系學生需要的中間步？
10. 引用是否支持所聲稱的結果，公式、元件和站內連結是否能正確呈現？

最後簡短報告實際改動與必要限制；不要以整段規則重述代替交付內容。

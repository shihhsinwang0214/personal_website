> 第一週最容易被浪費的方式，是卡在裝環境、找不到人問，然後自己悶著。這一頁就是要避免那個。

## 你可以找誰

第一次一對一的時候，我們會一起把下面這張表填完。角色可以由同一個人兼任，但我不希望有任何一格是空的——空的那格通常就是你之後會卡住又不知道找誰的地方。

| 找誰 | 什麼事 |
|---|---|
| 我（指導教授） | 研究方向、題目值不值得做、品質標準、重大決策 |
| 主要 mentor | 起始任務、示範、日常討論與回饋 |
| 備援 mentor | 主要 mentor 不在時 |
| 技術支援 | 環境、程式、資料、運算資源 |
| 日常求助頻道 | 一般問題，Slack 上的哪個頻道 |
| 敏感或衝突的事 | 不方便公開講、也不方便直接跟 mentor 講的時候 |

最後一格特別重要。你不太可能用到，但知道它存在，跟真的需要時才臨時去找，是兩件事。

## 一次低風險的起點盤點

開始之前，我們會聊一次你目前的狀態：跟任務相關的數學、程式、Git、Linux 與領域背景；有沒有讀過論文、重現過結果、診斷過實驗；你實際上可以投入多少時間；有沒有需要特別安排的地方。

**這不是考試，也不會拿來推論你的能力上限。** 它只用來決定一件事：從哪一層鷹架開始比較不會浪費你的時間。說得越誠實，我們越不會把你放在錯誤的難度上。

## Start Here：不要一開始就讀完所有東西

主要 mentor 會給你一份不超過五項的清單，並且標好每一項屬於哪一類：

- **核心材料**：現在就需要理解的；
- **任務工具**：遇到具體問題時再查的；
- **延伸材料**：知道放在哪裡就好，第一個月不用讀完；
- **暫時不用讀**：跟你的起始任務沒有直接關係的。

我看過太多新人把第一個月花在讀一大堆論文，然後什麼都沒動手。如果你不確定某份材料屬於哪一類，直接問，不要自己猜。

## 環境要先跑得起來

起始任務會事先確認：目標結果長什麼樣、參考環境是什麼、合理誤差多少、大概要跑多久、運算預算多少、已知會壞在哪裡、什麼時候該停下來問。

你這邊要做的：

- 把 Slack、GitHub、運算資源、共用資料與必要軟體都設定好；
- 跑一個成本很低的 smoke test，確認權限與環境真的能用；
- 把這個 smoke test 記下來，之後環境出問題時，你可以先跑它來判斷是環境壞了還是程式壞了。

如果環境卡超過半天，請直接找技術支援，不要自己耗。這件事沒有任何學習價值，把時間留給真正的問題。

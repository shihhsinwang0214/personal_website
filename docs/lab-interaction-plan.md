## 三個篩選問題

任何互動提案，先過這三關。過不了就不做——這是煞車，不是清單。

1. **它替讀者做了什麼事？** 說不出一句具體的話（「幫他在 22 頁裡找到現在需要的那一頁」），
   就是裝飾。
2. **沒有 JS 的時候，內容還完整嗎？** 互動只能加，不能減。手冊是內容網站，
   不是應用程式。
3. **它會不會替代掉我們真正想要的行為？** 這關最嚴，也最容易漏。
   一個很便宜的點擊，可能讓人覺得「我已經處理過了」，於是不去做那件真正有用的事。

第三關直接殺掉了下面兩個原本看起來不錯的提案（見「重新評估後反對」）。

## 建議做

### A. 症狀分診：「我現在卡在哪？」

**頁面**：`/handbook/bestiary`

頂部一排症狀按鈕（環境壞了／重現不出來／不敢問／看不到進展／時間不夠／被 reviewer 打），
點了就篩選卡片；另外給一個純文字搜尋框。

**它替讀者做什麼**：真正會有人打開圖鑑的時刻，是「我現在很挫折」。那個時刻沒有人
有耐心讀 13 張卡片。這是一個分診工具，不是目錄。

**沒有 JS**：13 張卡照常全部列出，跟現在一模一樣。

**成本**：小到中。資料已經在 `src/lib/bestiary.ts`，需要多一個 `symptoms: string[]` 欄位。

**這是整份規劃裡我最推薦的一項**，因為它是唯一在使用者最需要的時候介入的設計。

### B. 路線圖：走過的節點會亮

**頁面**：研究室首頁的技能樹（順帶側欄）

讀過的頁在技能樹上點亮，沒讀過的維持空心。只存在瀏覽器，只有本人看得到，
旁邊固定放一個「清除紀錄」。

**它替讀者做什麼**：手冊有 22 頁分四區。新成員讀了兩週之後不知道自己漏了什麼。
點亮的是**內容的覆蓋範圍**，不是任何人的表現。

**為什麼不違反規則**：`lab-rpg-rules.md` 說「節點計數是內容的長度，不是誰的成績」。
同一個道理——這裡點亮的是「這一頁被走過了」，沒有評價走過的人。

**必須守住的界線**：**不顯示百分比、不顯示「完成度」三個字、不顯示任何總分。**
一旦出現 18/22 或 82%，它就變成打分數，整條規則就破了。

**沒有 JS**：全部顯示為未點亮，不影響任何導覽功能。

**成本**：小。一次 localStorage 寫入加幾行 CSS。

### C. 首頁「你是誰？」路線選擇

**頁面**：研究室首頁

三個按鈕：我在考慮申請／我剛加入／我是合作者。點了之後高亮對應的路線並捲過去。

**它替讀者做什麼**：22 頁四區，第一次來的人不知道從哪裡讀起。

**現成的**：`roleCards` 這份資料已經寫在 `src/lib/handbook.ts`，但目前**沒有任何頁面在用它**。
這正是它原本的用途，撿回來用就好。

**沒有 JS**：技能樹照常全列。

**成本**：小，資料已存在。

### D. 名冊的鍵盤操作與可分享連結

**頁面**：`/handbook/people`

↑↓ 或 j/k 切換成員；選到的人寫進網址 hash，讓 `#member-3` 這種連結可以直接開到某個人。

**它替讀者做什麼**：可分享連結是真的需求——學生會想把自己的卡片傳給家人或朋友。
鍵盤操作只是順帶，成本幾乎是零，而且強化選單的感覺。

**成本**：很小。

### E. 404 改成「路線尚未開通」

404 已經是失敗狀態，是全站唯一**花俏不會有代價**的地方。lab 區底下的 404
可以依路徑給不同文案（`/handbook/*` 用遠征用語，其他維持現在的英文版）。

**成本**：小。`src/pages/404.astro` 已存在。

6–8 題自我檢測，可以照抄既有的 `src/components/Quiz.astro` 模式（notes 已在用）。

## 一律不做

| 提案 | 為什麼不 |
|---|---|
| 經驗值條、等級、成就徽章、連續天數 | 都需要替學生打分數 |
| 排行榜 | 同上，而且製造內部競爭 |
| 音效、掃描線、CRT 濾鏡、打字動畫 | 純裝飾，且傷可讀性 |
| 死線倒數的「Boss 血條」 | 把焦慮做成介面 |
| 追蹤誰讀了哪些頁並回報給 PI | **這條寫死。** 所有紀錄留在讀者的瀏覽器，我看不到 |
| 彩蛋（Konami code 之類） | 沒有對應物，違反第一原則 |

最後那條值得在頁面上**明講**：「這些紀錄只存在你的瀏覽器裡，不會傳出去，我也看不到。」
一句話就把一個可能讓人不安的功能，變成一個信任聲明。

## 共同技術約束

1. **Progressive enhancement**：所有內容在沒有 JS 時完整可讀。互動只加不減。
2. **`prefers-reduced-motion`** 一律遵守（`global.css` 已有三處在用，照抄）。
3. **狀態只存 localStorage，永不送出**；每一個有記憶的功能都要有「清除」。
4. **鍵盤可操作、有 focus 樣式**；分級不能只靠顏色（圖鑑已遵守：tier 有文字標籤）。
5. **不引入框架。** `Quiz.astro` 與 `PeopleView.astro` 的 inline script 是現成樣板。
6. **View transitions**：站上有 view-transition 導航，script 必須能重新綁定——
   照 `HandbookArticle.astro` 的 `initHandbook()` 寫法。

## 建議順序

A（分診）→ B（路線圖）→ C（你是誰）→ D（名冊連結）→ E（404）。F 等你決定。

理由：A 是唯一在讀者最需要的時刻介入的；B 對新成員最有用；C 成本最低而且資料已經寫好了。

## 成員照片：正面／反面與裁切

成員卡的照片可以點一下翻面（`Person.photoAlt`）。翻面鈕只在那個人**真的有第二張**
時出現，而且是由 script 顯示的——沒有 JS 時照片就只是照片。
`prefers-reduced-motion` 時直接換圖，不播翻轉動畫。

### 檔案慣例

```
public/images/people/
  <名字>.jpg          原始檔（不動它）
  <名字>-反.jpg       原始檔，比較調皮的那張
  <名字>-card.jpg     720×960 直式裁切（3:4）  ← 程式引用的是這個
  <名字>-反-card.jpg
```

原圖一律保留，程式只引用 `-card` 版本。這樣重新裁切不會弄丟原始檔。
檔名有中文與空白沒關係，`PeopleView.astro` 會 `encodeURI()`。

### 重新裁切

原圖多半是直式或橫式，直接用 `object-fit:cover` 會從額頭或下巴切過去。
下面這段用膚色偵測（YCrCb）估出臉的位置，再把臉放在方框上方約 42% 的地方：

卡片照片是固定的 **3:4 直式方塊**（來源裁切 720×960），不隨文字欄高度伸縮。
曾經讓它 `align-self:stretch` 去對齊文字欄高度，結果每張卡的 `cover` 裁法都不同，
看起來像圖片載入後又被自己修掉一塊——不要再這樣做。

```python
# 在 site/public/images/ 底下執行
import numpy as np
from PIL import Image
W_OUT, H_OUT, AR = 720, 960, 0.75
def skin_centre(im):
    small = im.resize((160, int(160*im.size[1]/im.size[0]))) if im.size[0] >= im.size[1] \
            else im.resize((int(160*im.size[0]/im.size[1]), 160))
    a = np.asarray(small).astype(np.float32); R, G, B = a[...,0], a[...,1], a[...,2]
    Y = 0.299*R + 0.587*G + 0.114*B
    Cr = (R-Y)*0.713 + 128; Cb = (B-Y)*0.564 + 128
    m = (Cr>=133)&(Cr<=180)&(Cb>=77)&(Cb<=130)&(Y>40)
    if m.sum() < 60: return None
    ys, xs = np.nonzero(m)
    keep = ys <= np.percentile(ys, 60)      # 臉在手和手臂上方
    ys, xs = ys[keep], xs[keep]
    w, h = small.size
    return xs.mean()/w, ys.mean()/h
def crop(src, out, place=0.38, zoom=1.0):
    im = Image.open(src).convert('RGB'); W, H = im.size
    ch = int(zoom * min(H, W/AR)); cw = int(ch*AR)
    if cw > W: cw = W; ch = int(cw/AR)
    c = skin_centre(im)
    cx, cy = (c[0]*W, c[1]*H) if c else (W/2, H*0.35)
    left = int(max(0, min(W-cw, cx - cw/2)))
    top  = int(max(0, min(H-ch, cy - ch*place)))
    im.crop((left, top, left+cw, top+ch)).resize((W_OUT, H_OUT), Image.LANCZOS).save(out, quality=88)
```

全身照要另外給 `zoom`（例如 `zoom=0.62`），否則臉在 150px 的欄位裡會小到認不出來。
**裁完務必把成品排成一張 contact sheet 看過一遍**——膚色偵測會被木頭、衣服、
暖色牆面騙到，用看的兩秒就知道有沒有切壞。

有些照片自動裁不出來，要手動給座標：PI 的兩張就是。滑雪那張**不能切到雪板**
（構圖是橫的，自動裁一定會切掉）；Arches 那張要在「認得出是他」和「看得到拱門」
之間取捨——因為同一個檔案也會被縮成 34px 的名冊頭像，所以優先讓人臉夠大。
這兩張在腳本裡是寫死的 `crop_box()` 座標。

注意名冊頭像與詳情卡共用 `photo` 欄位。挑正面照時記得它要在 34px 下還認得出來，
太廣角的全身或風景照不適合當正面。

### 踩過的坑：`[hidden]` 不一定會隱藏

任何有設 `display:` 的 class 都會蓋掉瀏覽器內建的 `[hidden]{display:none}`。
沒有照片的人，他的字母替代圖（`.person-monogram` 是 `display:flex`）就這樣一直
留在照片下面變成一個空方塊。這頁還有好幾個元素用同樣方式開關——翻面鈕、連結列、
自我檢查的選項、技能樹圖例——所以 `global.css` 裡放了一條
`[hidden]{display:none !important}` 一次解決整類問題。新增用 `hidden` 開關的元件時
不必再各自處理。

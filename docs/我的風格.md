# 我的筆記視覺風格

這份文件定義 diffusion、flow matching、machine learning foundations 與 mathematical foundations 筆記的靜態教學圖風格。

## 0. Source of truth 與優先順序

視覺判斷依照以下優先順序：

1. `design/style-references/user-approved/` 內的 9 張使用者核准參考圖。
2. U1.0–U1.2 現有貓圖與 Week 2 簡報 `dma-w2-overview.pptx`。
3. 原始 `<VizPlan>`：公式、數值、方向、反例與科學條件的內容 source of truth。

若較舊規格與 9 張核准參考圖衝突，以核准參考圖為準；若視覺參考與數學內容衝突，以正文與 `<VizPlan>` 的科學正確性為準。

核准參考圖全部為 **1672 × 941，接近 16:9**。後續可製作 1920 × 1080，但必須維持相同比例與閱讀密度。

## 1. 一句話定義

這是一套「一張圖回答一個問題」的課堂投影片式視覺：大問題標題、單句前提、主要證據圖、精確數學錨點，以及底部一句 inference。

重點不是把一篇文章濃縮成一張 infographic，而是把推理拆成數張可以依序閱讀的單題圖。

## 2. 最重要的新規則：先拆題，再畫圖

### 2.1 一張圖只承擔一個認知動作

每張圖只能主要做其中一件事：

- 定義一個對象。
- 解釋一個方向或向量。
- 比較兩個設定。
- 展示一個演算法步驟。
- 指出一種誤差來源。
- 用一個反例排除常見誤解。

若原始 `<VizPlan>` 同時包含 posterior、conditional mean、Tweedie、三個時間狀態與 score，應拆成多張圖，而不是縮小字體全部塞進同一張。

### 2.2 一個原始 VizPlan 可以對應多張圖

預設不是「一個 VizPlan＝一張 PNG」。判斷方式：

- 只有一條完整推理：一張。
- 需要先定義、再比較、最後收束：兩到三張。
- 有三個彼此獨立的自由度或錯誤來源：先各自說清楚，再視需要補一張總結。

圖片檔名可使用 `-a`、`-b`、`-c` 或連號，正文依推理順序插入。

### 2.3 核准範例如何拆題

原本三個大題被拆成 9 張：

| 參考圖 | 只回答的問題 |
|---|---|
| `01-posterior-candidates.png` | 同一個 $x_t$ 為什麼可能來自多個 $x_0$？ |
| `02-posterior-mean.png` | squared-error denoiser 為什麼輸出 posterior mean？ |
| `03-tweedie-score.png` | posterior mean correction 為什麼就是 score direction？ |
| `04-schedule.png` | 固定端點時，schedule 改變什麼？ |
| `05-coupling.png` | 固定 marginals 時，pairing 改變什麼？ |
| `06-gamma-path-thickness.png` | $\gamma_t$ 是否讓 path 具有厚度？ |
| `07-exact-ctmc-vs-tau-leaping.png` | exact CTMC 與 τ-leaping 的核心差異是什麼？ |
| `08-tau-leap-step.png` | 一次 τ-leap 實際執行哪三步？ |
| `09-tau-leaping-errors.png` | 平行化帶來哪些誤差與成本？ |

這個拆法就是後續工作的標準。

## 3. 單張圖的固定敘事骨架

大多數圖片使用四層結構：

1. **問題式主標題**：位於最上方，直接說本圖要回答什麼。
2. **單句副標題**：補上前提、變因控制或主要答案方向。
3. **主要證據區**：占畫面最大面積，只呈現回答本題所需的 plot、流程、對照或幾何關係。
4. **底部結論條**：用一個完整句子收束，關鍵詞可用亮藍粗體。

必要時可在主圖與底部結論之間加入一條精確公式，但不要再擴充第二個主題。

## 4. 核准的構圖模式

### 4.1 單一主圖

適合 posterior、score、vector field、density 或 loss geometry。

- 主圖通常是一個大座標系或大示意圖。
- 右上可放小型 legend 或關鍵公式。
- 註解直接指向圖中對象，不另外建立大量說明卡。
- 例：`01-posterior-candidates`、`02-posterior-mean`、`03-tweedie-score`。

### 4.2 嚴格控制變因的左右／上下對照

適合 schedule、coupling、deterministic vs stochastic、exact vs approximate。

- 兩側必須共用端點、座標或 marginals。
- 標題明說「固定什麼，只改什麼」。
- 相同項目保持完全相同，只有被研究的變因改變。
- 例：`04-schedule`、`05-coupling`、`06-gamma-path-thickness`、`07-exact-ctmc-vs-tau-leaping`。

### 4.3 編號步驟

適合 sampling、optimization、algorithm trace。

- 使用 1、2、3 的大圓形步驟編號。
- 每欄只顯示該步驟的 before/after、機率與一個公式。
- 箭頭只連接相鄰步驟。
- 例：`08-tau-leap-step`。

### 4.4 並列的原因分析

適合三種 error、三個 failure mode 或三項 trade-off。

- 每欄使用不同但可比較的證據類型：曲線、分布、狀態轉移。
- 每欄下方有一句局部結論。
- 所有欄完成後，再用共同極限或總結式收束。
- 例：`09-tau-leaping-errors`。

卡片與等寬 panel 是允許的。它們不是裝飾，而是用來表示「可並列比較的同層概念」或「有順序的步驟」。禁止的是把不相干、不同層級的內容硬切成同尺寸卡片。

## 5. 畫布、留白與視覺密度

- 比例：16:9；核准參考為 1672 × 941，正式輸出可用 1920 × 1080。
- 背景：白色到極淡冷藍的柔和漸層，可有非常輕微 vignette。
- 四周保留約 2–3% 安全邊界。
- 大標題與主圖之間必須有明顯留白。
- 主圖通常占畫面高度約 55–65%；底部 conclusion strip 約 8–11%。
- 每張圖只保留 1 個主要視覺中心。即使是三欄圖，三欄也必須共同回答同一個問題。
- 可使用 1–2 px 淡藍邊框、16–24 px 圓角、極淡內部漸層。陰影只能非常輕，不能有厚重浮卡效果。

## 6. 標題、文字與公式

### 6.1 標題

- 主標題很大、置中、深海軍藍、粗體。
- 優先寫成問題或強結論，例如「誰跟誰配對？」、「一次 τ-leap 到底做什麼？」。
- 可以中英混排，但英文術語只在它比硬翻中文更準確時保留。

### 6.2 副標題

- 一句話說清楚控制變因或主要前提。
- 不重複標題，不先把所有細節講完。
- 常用句型：
  - 「固定 A，只改 B，會看到 C。」
  - 「速度來自 X；代價主要有 Y。」
  - 「觀察到 X 後，可能的 Y 不只一個。」

### 6.3 圖內文字

- 以短標籤為主，完整解釋留給副標題與底部結論。
- 圖內註解直接靠近被解釋的物件。
- 粗體只用於主詞、變因名稱與關鍵結論。
- 中英混排是核准風格的一部分：posterior weight、conditional path、joint correlation、remasking 等可以保留英文。

### 6.4 公式

- 公式使用數學襯線字；中文與一般英文使用無襯線字。
- 公式可以放在淡藍細框的小區塊內，但一張圖通常只突出 1–2 個公式。
- 圖中的公式必須是理解主圖所需的錨點，不是裝飾。
- 公式、中文、數值、座標與 legend 必須使用精確排版圖層，不交給圖像模型生成。

## 7. 色彩語意

核准圖的整體色彩比舊規格更冷、更乾淨，並允許紫色作為「觀測點／mask／中介狀態」。

| 色彩 | 建議色碼 | 固定語意 |
|---|---:|---|
| 深海軍藍 | `#071347` 或 `#0b2b6f` | 標題、正文、座標、主要公式 |
| 亮藍 | `#1769e8`／`#4a90e2` | source、noise、$x_0$、主要方向、關鍵字強調 |
| 橘色 | `#ff7a21`／`#f0803c` | target、data、$x_1$、新值 |
| 紫色 | `#7543d7` | $x_t$、`[MASK]`、中介狀態、需要重新決定的位置 |
| 紅色 | `#ef3340`／`#d94f4f` | posterior mean correction、錯誤、被特別指出的修正 |
| 綠色 | `#65b45d` | 已知 token、第三類狀態、輔助正例 |
| 中性灰 | `#8793a3` | 弱關係、未選擇、輔助說明 |
| panel 淡藍 | `#f4f8ff` | 比較區與步驟區背景 |

顏色必須承載語意。同一組 source/target 在整個系列中維持藍／橘；`[MASK]` 維持紫色；灰色表示未強調或輔助資訊。

## 8. Plot、箭頭與比較

- 座標軸使用深藍細線，箭頭明確但不巨大。
- 曲線、contour、point cloud 與 token 是主角；panel 背景退後。
- 線寬可表示 posterior weight，但必須附 legend。
- 比較圖的圖例只說必要 mapping，不重述正文。
- 箭頭表示真正的數學方向或狀態變化；終點必須落在實際目標。
- 重要等價關係可使用 `↔` 或兩支同方向箭頭，但應在旁邊放精確公式。
- 同一比較中的座標尺度、端點、marginals 與 token 位置必須對齊。

## 9. 底部結論條

每張圖幾乎都需要一條底部 conclusion strip：

- 淡藍白底、細藍框、圓角。
- 一個完整句子，不超過兩行。
- 只說本圖剛剛證明的 inference。
- 1–2 個關鍵詞可用亮藍粗體，例如 `posterior distribution`、`conditional vector field`、`finite-τ`。
- 不寫口號，不新增圖中沒有證據支持的主張。

## 10. 動物的使用規則

核准的 9 張圖完全不依賴動物，因此狗不是每張圖的必要元素。

- 只有當需要表示真實 data sample、mode、input/output 或生成結果時才放狗。
- 狗是資料，不是講者、教授、操作員或 mascot。
- 不加對話框、職業服、大型道具或誇張表情。
- 若抽象點、token、density contour 已足以解釋概念，就不放狗。
- 若同一 sample 沿時間變化，狗的身份、視角與構圖必須保持一致。

## 11. 製作方法

- 先從 `<VizPlan>` 與正文整理完整推理鏈。
- 把推理鏈拆成數張「問題 → 證據 → inference」單題圖。
- 先完成無裝飾 wireframe，確認每張只回答一題。
- 使用 SVG 精確繪製公式、文字、plot、箭頭、token、表格與數值。
- ImageGen 只用於資料照片、狗、生成結果或確實需要的插畫素材。
- 保留可編輯 SVG master，再輸出 PNG。
- 不截取 HTML demo 當作靜態教學圖。

## 12. 不要再做的事

- 把 posterior candidates、posterior mean、三種時間狀態與 Tweedie 全塞進一張圖。
- 把 schedule、coupling、$\gamma_t$ 與四方法表格全部塞進一張總覽。
- 把 τ-leap 的步驟與三種 error source 混成一張密集流程圖。
- 為了維持原定圖片數量而拒絕拆圖。
- 用相同的三欄卡片模板處理所有題目。
- 用大量小字補救過度濃縮的構圖。
- 讓插畫、狗或裝飾道具取代 plot 與精確公式。
- 生成式假文字、錯誤公式、含糊刻度或沒有對齊的比較。

# From Noise to Data — 撰寫語氣與互動題慣例

這份文件記錄「From Noise to Data」系列 notes 的寫作風格，給未來補寫或改寫時當依據。
目標讀者：大學高年級、研究生初期、想進 AI/ML 研究但常卡在「直覺與公式之間」的人。
核心定位：**通往研究理解的數學橋樑**——先讓人敢進來，再帶他到正式數學與研究脈絡。

---

## 聲音（voice）

- 邀請，而不是診斷。語氣是「我們換個角度看」，不是「你卡住了」。少用「卡點」。
- 低壓、清楚、直接。能刪的字就刪。不賣弄術語；第一次出現的符號就定義。
- 一篇一個主概念。先給畫面，再接回數學，最後接到研究與下一步。
- 鼓勵但不雞湯。可以說「如果你已經能想像 X，那你其實已經抓到一半直覺了」，但要扣著內容，不要空喊。
- 誠實標示範圍：講清楚這篇做什麼、不做什麼；正式事實、直覺、研究用法、簡化假設要分得出來。
- 數學必須正確。不確定就標 TODO，不要用聽起來合理的話填洞。

## 每篇的內在骨架（保留邏輯，但把標題藏起來）

順序大致是：場景化開頭 → 換個角度的問題 → 一句話直覺 → 最小例子（常配 demo）→ 翻成數學 → 容易想歪的地方（配選擇題）→ 接到論文 → 下一步 →（參考文獻）。

**但每篇的段落標題要不一樣**，不要讓讀者看到固定模板。可用的變體：

| 功能 | 標題變體（每篇挑不同的） |
|---|---|
| 開場/動機 | 先換個角度、為什麼這件事值得想、先別被符號嚇到、公式裡突然多出一個東西、從「一條路」到「一張地圖」 |
| 一句話直覺 | 先記這一句、先抓住這個畫面、最重要的圖像 |
| 最小例子 | 用一個小例子看見它、先在 2D 裡看看、用 two moons 看見它 |
| 正式數學 | 把畫面寫成數學、把圖像翻成數學、現在寫成公式 |
| 常見誤解 | 幾個容易想歪的地方、讀到這裡先別急著這樣想 |
| 研究用法 | 這怎麼接到論文？、為什麼研究者在乎？、這接到哪些方法？ |
| 下一步 | 下一步、接下來 |

## 開頭：場景化引入

每篇開頭用「讀者此刻正在看到/想到的東西」破題，讓他覺得「這就是我剛剛也在想的問題」。例如：看到 diffusion 動畫一團 noise 變圖片、看到一張全是箭頭的圖、公式裡冒出一族 $p_t$、密度怎麼會自己變。

## 比喻庫（已用過，避免重複）

黏土（noise 是原料）、走廊裡的人（continuity）、兩張照片 vs 中間那段影片（probability path）、在每顆點貼標籤（Lagrangian 軌跡）、天氣風場 / 導航規則（vector field）。新篇章盡量用新比喻。

## 互動選擇題（MDX `<Quiz>` 元件）慣例

元件：`src/components/Quiz.astro`。在 `.mdx` 裡 `import Quiz from '../../components/Quiz.astro';`。

```mdx
<Quiz
  q="問題敘述（盡量是讀者自然會問的）"
  options={[
    { text: "選項",          explain: "為什麼這樣想會偏掉" },
    { text: "正解",  correct: true, explain: "為什麼對、以及一句延伸直覺" },
    { text: "選項",          explain: "點出常見錯誤的根源" },
  ]}
/>
```

規則：

1. **正解位置要隨機分散**——不要每題都把 `correct: true` 放第一個。跨整個系列輪流放在 0、1、2、3。
2. **一篇可以放多題**，不必只放一題。把不同迷思拆成不同題，或在不同段落穿插。
3. 每個選項都要有 `explain`，包含錯誤選項——解釋「為什麼會這樣想、為什麼偏掉」，這才有教學價值。
4. 選項是貌似合理的迷思，不是明顯亂答。題目用讀者真的會冒出的疑問來問。
5. 把選擇題當成「消化觀念」的工具：放在「容易想歪的地方」段落，讓讀者先自測、再讀解釋。

## 數學與記號（全系列一致）

- 時間 $t\in[0,1]$，$p_0=\mathcal N(0,I)$（noise）、$p_1\approx p_{\text{data}}$（data）。
- 樣本/粒子 $x_t$；速度場 $v_t(x)$；條件速度 $u_t$；score $s_t(x)=\nabla_x\log p_t(x)$。
- 加噪 $x_t=\alpha_t x_0+\sigma_t\epsilon$。**注意**：diffusion 論文常用相反時間方向（$t=0$ 資料、$t=T$ 噪聲）；遇到時明確提醒。

## 數學專有名詞用英文（重要）

數學的 technical term 一律用**英文**，鑲在中文句子裡；不要翻成中文術語。例如：

- 寫「假設這個 vector field 是 smooth 且 time-dependent 的」，**不要**寫「假設這個向量場是光滑的、時間相依的」。
- 一個 term 在一篇 note 裡**第一次出現**時，給一句**白話**解釋（不是中文術語對照），之後就直接用英文。例：「這裡假設 $f$ 是 bounded 的（值不會跑到無限大）。」

常見對照（用右欄的英文）：

| 不要寫 | 要寫 | 不要寫 | 要寫 |
|---|---|---|---|
| 有界 | bounded | 光滑 | smooth |
| 時間相依 | time-dependent | 連續 | continuous |
| 可微 | differentiable | 梯度 | gradient |
| 散度 | divergence | 期望(值) | expectation |
| 條件期望 | conditional expectation | 變異數 | variance |
| 機率密度 | probability density | 分布 | distribution |
| 邊際 / 聯合 / 條件 | marginal / joint / conditional | 收斂 | convergence |
| 線性 | linear | 凸 | convex |
| 單調 | monotone | 向量場 | vector field |
| 範數 | norm | 內積 | inner product |
| 雅可比 | Jacobian | 支撐 | support |
| 漂移 / 擴散 | drift / diffusion | 隨機過程 | stochastic process |

一般白話（不是 technical term）仍用中文，例如「往哪走」「越來越密」「搬運」這些不要硬翻成英文。判準：它在數學課本裡是不是一個有定義的名詞？是 → 用英文；只是日常描述 → 用中文。

## 節奏：一次只引入一個物件（重要）

讀起來太快、一段塞太多新物件，是最常見的失敗。對齊 From Noise to Data 的漸進感：

1. **一篇 note 只正式引入一個新物件**（一個 definition / 一條公式 / 一個 term）。需要第二個,通常該拆成下一篇。
2. **問題先行**：先讓讀者感到「我為什麼需要這個東西」，再給它。每個物件都從一個卡住的具體情境長出來，而不是憑空宣布定義。
3. **先畫面、後符號**：先用生活化或幾何 picture 建立直覺，符號只在 picture 站穩之後才出現；出現時逐一拆解每個記號的意思。
4. **寧可多拆幾篇短 note**，也不要一篇硬塞完一整個 lecture。課程的一個 lecture → 通常 3–5 篇(甚至更多)短 note,每篇一個 idea。
5. 介紹完一個物件,用一句話**回扣它解決了開頭那個問題**,再交棒到下一篇。

> 自我檢查:如果一篇 note 在三段內出現三個以上第一次見到的 term/公式,它幾乎一定太快了——拆開。

## 中繼資料（frontmatter）

每篇 `.mdx` 開頭一定要有合法 frontmatter（否則 content collection 會建置失敗）：
`slug, lang, title, category: "research-areas", group: "From Noise to Data", status, updated, summary, demos, references`。
slug 一旦註冊到 `src/lib/notes.ts` 的 `noteSlugList` 就不要改（排序、英文 stub、跨篇連結都靠它）。

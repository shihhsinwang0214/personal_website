# 課程筆記的最低完整度：以 U4.0 為基準

作者於 2026-11-01 確認：目前的 U4.0「資料是 Token 的時候，噪聲是什麼？」可以作為今後筆記的最低完整度。這份文件將它的教學方式寫成可執行的編輯與驗收標準；不是只對 U4 有效的模板。

搭配 [課程筆記改寫準則](dma-notes-style-guide.md)、`intuition-first-academic-teaching` 與 `concept-ordered-math-writing` 使用。作者逐句提供的文字與後續指示優先。完整度指讀者能走完一條推理，不是篇幅、元件或圖片的數量。

## 每篇都要讓讀者走完的過程

**前一篇留下的問題 → 生活直覺中的一個動作 → 可以檢查的數學 → 實際執行這個動作 → 觀察結果 → 回答問題，再提出下一個缺口。**

五個部分都要有，而且要描述同一件事：

| 必備部分 | 讀者應該能回答 | U4.0 的對照 |
| --- | --- | --- |
| 問題啟發 | 為什麼現在需要這個方法？ | 圖片能加噪，一句話要怎麼逐漸失去資訊？ |
| 生活直覺與方法動機 | 生活裡的哪個動作，讓我們想到這個設計？ | 克漏字、盲猜換字；全 MASK 或均勻分布很容易製造，因此可作生成起點 |
| 數學與漸進說明 | 式子在描述什麼？每項為何存在？ | 從單格機率表、categorical sampling，走到保留與重抽的 PMF interpolation |
| 可執行的程式 | 這個式子實際怎麼產生一個結果？ | 在頁面修改並執行 Python，抽出不同時間的 noisy states，再重複抽樣觀察比例 |
| 幫助理解的圖解 | 看圖能比只讀文字多看懂什麼？ | 逐漸遮住整句話；對照遮蔽與隨機換字 |

不能只在一篇末尾依序附上五種材料。例子、符號、圖、程式必須互相對得上，讀者應該能指出程式的哪個動作對應公式的哪一項。

## 問題和生活直覺怎麼接到方法

- 起頭先回指已經會的事，再指出具體缺口。方法名稱不代替動機。
- 生活例子要讓讀者想到一個可實作的動作，例如遮住、重抽、換房間、根據新 context 改答案。不能只有「很像某件事」。
- 保留從直覺到設計的思考：為什麼選這個端點？這個操作怎麼控制中間狀態？它如何幫助生成？精簡時刪重複與旁支，不刪這幾步。
- 沿用同一個例子。若為了顯示某個限制，必須改用 parity 等 toy，先說原例子還看不出什麼，才換例子。
- 選擇教學主線時，以該領域目前具代表性的常用做法為依據，查核原始論文或官方實作。Toy 用來逐步解釋這個做法；不要因為某種表述比較容易舉例，就把它寫成實際模型的預設流程。分清數學分析採用的基本事件、模型真正預測的量與有限步抽樣器的操作。
- 標題和置中提問寫一般性的問題。七成保留、第三格等細節放進內文當例子，不拿特殊數字代替整節的問題。
- 不使用「先不急著」「值得停一下」等作者未採用的安撫或指示口吻。讓閱讀順序本身形成節奏。

## 數學要讓讀者跟著建立

- 先指出想算什麼與已知條件，再寫公式。第一次出現的符號就地解釋，不集中成篇首符號表。
- 用具體數字或小表格算一次，再推廣到一般式；一般式之後要能回代原例子。
- 每條新式子後說出它實際做的動作。不能只有記號的中文讀音。
- 核心 loss、posterior、守恆式、更新規則依思考順序使用精簡 `FormulaSteps`。提供逐步、回起點與一鍵到底；不把 routine algebra 全做成動畫。
- 位置索引使用括號上標，例如 $x_0^{(3)}$、$q_t^{(\ell)}$，避免看成次方。樣本編號、迭代編號與真正的冪次，另外交代角色。
- 用 column vector 展示離散 PMF；若 $R(i,j)$ 表示 $i\to j$，就沿用 $\dot p_t=R_t^{\mathsf T}p_t$。不能在證明中突然換成 row vector。
- 分清 reference PMF、一次抽出的 state、理想 dynamics、模型近似與有限步 sampler。增加抽樣次數只能看清該 sampler 的分布，不能消除它本來的偏差。
- 保留結論成立的條件，但不要讓旁支與免責說明淹沒主線。完整推導若是理解答案所需，就不能只說「可以證明」。

## 程式必須能在筆記裡實際執行

- 每篇至少有一個對應核心問題的可執行小實驗。預設沿用網站的瀏覽器 Python 元件，能編輯、執行、看結果並還原；提供同一份程式下載。
- Pseudocode 與數學 pipeline 可以補充，但不能取代真正能執行的程式。按鈕也不能只播放預先寫好的結果。
- 控制項放在程式前面：資料、時間、seed、樣本數、步長或方法。讓讀者知道改哪一項能檢查哪個想法。
- 先告訴讀者要比較什麼，再跑結果；結果回扣該篇的式子與限制。單一結果看不到分布時，就重複抽樣並印出頻率。
- 簡化模型可以使用資料查表或精確 posterior，但要明講。不能把 oracle 稱為訓練好的 neural network；若主題是學習，就真的展示參數如何更新與 loss 如何變化。
- 不在每篇重建大型 training framework。小實驗要能獨立跑完，原本的完整實作篇仍負責模型與資料集的延伸。
- 實測原始程式、修改一個參數後的程式及還原功能。第一次下載環境的等待、失敗與停止狀態要可理解。

## 圖解要在讀者需要它時出現

- 每篇的核心機制至少有一個直接出現在正文的圖解，不能全部藏在延伸閱讀。
- 圖可以是既有圖片、投影片、原生 HTML／SVG 或可操作視覺。優先選學生看得懂的形式，不為圖片配額增加裝飾。
- 圖中的句子、時間方向、數字、符號必須與正文一致。舊圖若混入不相關的主題或錯誤暗示，改圖、換圖或移到有需要的補充；圖說不能替錯圖補救。
- 靜態圖用來看清機制；程式或 demo 用來觀察變動與隨機結果。兩者各有工作，不重複堆同一份內容。
- 複雜內容允許整頁圖片，也允許裁切。判準是學生是否能理解，而不是一律裁掉標題或縮成小圖。
- 手機上文字要可讀；圖表置中，不溢出；需要放大時提供入口。

## 刪除、改寫、增編的順序

1. 先列出該篇真正的問題鏈與前後篇分工。
2. 保留作者已確立的語氣、例子與數學角色。
3. 刪重複回顧、提前分類、與本篇問題無關的圖或段落。
4. 在讀者會卡住的轉換補動機、定義、算例或推導。
5. 補圖解與可執行範例，讓它們檢查同一個核心機制。
6. 將延伸文獻、一般化與完整技術細節收進補充，更新目標、quiz、bridge、摘要與舊錨點。

不要先堆素材再要求讀者自己找主線。也不要把「更短」當作完成：正文應短到沒有重複，完整到學生能重建下一步。

## 交付前驗收

- [ ] 不看補充，能說出本篇問題、動機、做法與答案。
- [ ] 生活例子真的帶出方法，數字能回代公式。
- [ ] 核心公式可逐步閱讀；符號、條件、時間方向一致。
- [ ] 正文圖解對應當前例子；不是只在末尾裝飾。
- [ ] Python 在實際頁面跑過，也改過一個條件；輸出是實際計算結果。
- [ ] 模型學習、oracle 與 sampler 近似都有正確標示。
- [ ] 抽樣統計與理論目標分開，沒有把有限次觀察當成普遍保證。
- [ ] MDX、KaTeX 與內容檢查通過；公式完整展開後仍可讀。
- [ ] 桌面與手機、亮暗主題看過；折疊內容、程式區和公式無裁切。
- [ ] 作者提供的文字以取代方式修改；刪改的重點與理由有紀錄。

### 2026-11-01 試用後的刪改紀錄

- **U4.1：保留作者已確立的講解與五張 context 圖。** 刪去「要生成整句話」中重複回顧的段落，讓 state 從單格推廣到整句的段落單獨承擔新問題；新增矩陣更新與 Monte Carlo 轉移實驗。
- **U4.2：補回從克漏字到 conditional rate 的思考。** 用同一個 masked input 配到不同 labels，連起 posterior、CE 與生成 rates；撤下沒有對應正文 MASK 例子的舊通用圖，改用原句、input、PMF 與數值 rates 的對照圖。新增真正更新參數的分類實驗，將時間加權、uniform、配對與應用合收為延伸閱讀。
- **U4.3：讓翻開時間和填字機率分開看。** 新增翻開機率的逐步公式與完整抽樣圖解，再接可執行的全 MASK sampler；D3PM、ELBO、ratio／SEDD 留在同一組延伸閱讀，不打斷正文生成流程。
- **U4.4：從熟悉的句子搭配出發。** 用「吃麥當勞／打籃球」重寫主線與 joint 圖，直接算出同批填字的錯配機率與 FE；parity 保留為較一般的補充。撤下混有連續局部直線近似的舊圖，避免讀者在本篇分心追另一個問題。新增精確 conditional 下的三種填字分組實驗。
- **U4.5：把修改需求接到可實作規則。** 補上 flow 補償的逐步公式，把有限步 kernel 與 pseudocode 從折疊補充移到正文；修正證明中的 column vector 記號為 $C_t^{\mathsf T}p_t$。新增固定時間的 CTMC 修改實驗，同時觀察分布與單一樣本的「字 → MASK → 重選」。

五篇的位置上標統一加括號；先備只列正文真正需要的內容，不把本篇即將建立的 CTMC 或補充中才使用的進階主題當作閱讀門檻。保留既有 label、slug 與必要的舊標題錨點。

驗收包含五份程式的實際頁面執行、修改參數與還原，並檢查機率總和、CE 更新、生成端點、joint 錯配及新增 generator 的淨效果。手機檢查包含完整展開的公式與延伸閱讀；過長的公式以換行修正，不縮小字體或截去內容。抽樣數字只作這些固定 toy 設定的觀察，不作一般品質保證。

### 2026-11-02：修正單格到 sequence 的斷點

- U4.1 從 U4.0 的「已知原句、直接抽 snapshot」提出相鄰時間轉換的問題。單格的 column vector、Markov chain 與 rate 先建立，再明列五個位置各自使用的轉移 PMF；新圖與逐步公式對上同一份 token 陣列。
- 正文實驗改為真正更新五格 sequence，再比較單格比例與一個完整句子的機率；原本的三狀態矩陣實驗、抵消 flow 與 HTML demo 保留為補充。完整矩陣驗算折起，保留正文的流入減流出機制。
- 撤下末尾重複介紹逐格處理、joint 與模型輸出的三段拼接。生成方向只提出尚未知的填字規則，由 U4.2 推導原字 PMF 與 rates、U4.3 負責有限步生成；U4.2 開頭同步接回這個缺口。
- 不讓讀者在前半篇把 state 只理解為 token、到最後才突然換意義。從開頭就保留整句的畫面；單格 toy 是固定其餘位置後的特例，逐格更新始終放回原來的 sequence 位置。


### 2026-11-03：由 U4.0 的 reference interpolant 直接推出 rate

作者進一步確認：U4.1 的 rate 應承接 U2 的 velocity，而不是讓 Markov chain 成為另一條開場主線。以下分工取代前一天先推加噪矩陣、再於 U4.2 推導填回 rate 的安排。

- U4.1 固定一筆已知原句，從 U4.0 的 conditional PMF 與 I_t 出發，選擇只把 MASK 填回原字的 reference 轉換。先算需補回的質量與每個 MASK 的翻開機率，再縮短時間得到 conditional rate；不能宣稱 PMF snapshots 唯一決定跨時間的過程。
- 「原字或 MASK」的單格推導直接用到整句。正文圖解、逐步公式與可執行 Python 都示範同一份原句的分批填回；機率守恆、矩陣與 CTMC 在推導之後解釋這條規則。舊的加噪三狀態圖不再放在這條主線。
- U4.2 不再重推 conditional rate，接手「生成時不知道原句」：原字 posterior、conditional rates 的平均與 CE 學習。想／要的 70:30 資料比例例子移到這裡，在未知原字真正出現時介紹。
- U4.0 的結尾同步改成 I_t → reference rate → 未知原句的學習問題。維持資料在 t=0、易抽樣分布在 t=1 的方向；reference state、已知原句的規則與模型生成仍分開。

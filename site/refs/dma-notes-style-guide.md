## 0. 三條底線

這一節是 2026-09-16 重寫的。前面兩週的規則是一條一條累積上去的，而 2026-09-15 那次作者的原話是「**我覺得你的 workflow 跟對我們 notes 的標準出現了很嚴重需要檢討的問題**」。回頭看，那一輪出錯的三件事都不是筆誤，是**預設動作**錯了。所以先把三條底線放在最前面，後面的細則都是它們的展開。

1. **每一條寫進正文的結論，本篇要推得出來。** 參考文獻是拿來對答案的，不是拿來引用權威的。判準：讀者問「為什麼」，本篇有沒有答案？沒有就要嘛推出來、要嘛整條拿掉。
2. **預設動作是取代，不是附加。** 作者的預設動作是刪，我的預設動作是加——這個落差要靠規則補。同一件事出現兩個版本，就是我沒有做決定。
3. **工具說通過，不等於通過。** 每一張截圖都要自己看過。2026-09-15 `shot2.mjs` 回報「display 溢出 0」，而那條式子在卡片裡明明被切掉了。

## 0-A. 接作者的稿

1. 作者會貼「段落位置 ＋ 他自己寫的版本」。**照他的字改上去**，只動三種東西：錯字、標點（半角 → 全角）、明顯的數學或術語錯誤。
2. **我自己補的內容要明講是我補的**，並說明理由（通常是「原句在數學上不精確」或「這裡缺一個銜接」）。
3. **被他的新版蓋掉、因此消失的東西也要一次列完**——尤其是粗體收尾句、blockquote、以及被吸收掉的整段。作者是在改一段話，不一定意識到那一改把某個結論整句刪掉了；我不提，它就無聲消失。
4. **作者貼過來的文字是從 render 過的頁面複製的，格式會掉。** `**`、`> `、`\sqrt`、上下標都會消失，KaTeX 還會把同一條式子重複貼成 `q(xt−1∣xt)q(x_{t-1}\mid x_t)q(xt−1∣xt)`，display 會變成 `[ … ]`。所以：**「他貼的版本沒有粗體」不等於「他要拿掉粗體」**，blockquote 與行內／display 的選擇同理。原本的照留，並在回報時說明我是這樣判讀的。
5. **localhost 連結一律換成 `<Ref>`**，`to=` 吃的是 frontmatter 的 `label` 不是 slug（見 §7）。
6. 回報時只講**「動了哪裡、為什麼」**，不要把整段貼回去。
7. 有一個真正需要作者決定的問題就問**一個**，其餘自己判斷後說明。**同一個問題最多再問一次**；問到第三次還沒被回答，就照我的建議做掉並標記。

## 0-B. 動筆之前的四個反射

1. **抄文獻的定理進正文之前，先問「本篇推得出來嗎」。**（底線 1 的展開。2026-09-15：我把《The Principles of Diffusion Models》Theorem 2.2.3 的**結論**直接抄進 W3.2，寫成「用 Jensen 不等式往上界，整理之後分成三項」，中間完全沒有推導——而同一篇裡有兩個 `<Try>` 正是在把等價定理與配方一步一步推給讀者看。）
   - **「整理之後就得到」「可以證明」「文獻上有一條推導」這類詞是警訊**，它們通常是我在掩蓋「我沒推」。
   - 重寫之後那一節是三步，每步一句話說清楚它憑什麼成立。**推完才發現右邊逐項就是本篇一開始寫下的 $\mathcal J$**——那個收穫是推導給的，抄結論永遠看不到。
   - **但「推導」不等於「每一步都展開」。** 作者要的是**每一步的機制被命名**（Jensen／對 $x_0$ 取期望／Markov structure），不是把代數全寫出來。我原本的錯是連機制都沒有，只有「整理之後」。
2. **作者問「可不可以改成 X」時，回答是把原本的換掉，不是把 X 加在旁邊。**（底線 2 的展開。）真的兩個都要留，必須說得出「為什麼讀者需要同時看到兩個」，並在回報時問。
3. **刪一段話或改一個標題之前，先 grep 它在別處有沒有被呼應。**
   - 刪段落 → grep frontmatter 的 `summary`、`<Objectives>`、篇尾收束段、以及 quiz 的 `<Explanation>`。（2026-09-15 刪掉 W3.3 一題 quiz 時，那題的解答是全篇唯一還寫著「整個推導對 $p_{\text{data}}$ 沒有任何假設」的地方。）
   - 改標題 → grep 全站有沒有別篇引用那個標題字串。W3.2 的「五行」被引用 13 次、橫跨 9 篇，是全課第二常用的 handle（僅次於 `conditional trick`）。
   - 併節或搬節 → grep「上一節」「下一節」「前面那一節」這種**相對指路**，它們會無聲地指錯。**回指要指內容，不要指位置。**
4. **術語、符號、語氣的掃除一次掃完整個單元，不要只改手上那一篇。** 半個單元用英文、半個用中文比兩者都糟。掃之前先 `grep -rn` 全站確認範圍，掃完再 grep 一次確認歸零。**grep 要搜裸的關鍵字**：搜「值得看／值得停」會漏掉「值得把⋯寫下來」（2026-09-15 當天就漏過一次）。

## 0-D. 改完怎麼驗、怎麼寫回

**寫回裝置**——`device_bash` 掛得起 `$HOME/mnt/site` 的時候（2026-09-15 起恢復），**直接在裝置上用 python read-modify-write 改**，不要走 stage／commit：

```
cd $HOME/mnt/site/src/content/notes/.../week-N
python3 - <<'EOF'
import io; p='...'; s=io.open(p,encoding='utf-8').read()
assert s.count(old)==1        # 護欄，永遠要
io.open(p,'w',encoding='utf-8',newline='').write(s.replace(old,new))
EOF
md5sum ...                    # 和容器裡驗過的那份對
```

- **`assert count==1` 是硬規定**，整段換掉時用「找開頭索引 ＋ 找結尾索引 ＋ 切片」。
- **不要重打整檔**；不要照著被截斷的 tool output 重新輸入內容。
- **驗證方式是 md5 對容器裡那份**，不是「看起來寫進去了」。

**mount 掛不起來時**才退回 `device_commit_files`，而它有一個會咬人的快取（2026-09-13 在 `w5-1` 實測：`device_stage_files` 自己也有快取，所以「stage 回來比 md5」會給假陰性）。四步驟：(a) 每次用**沒用過的 staged 檔名**、永遠不要覆蓋回已 commit 過的路徑；(b) 帶上該檔案**當下**的 `expectedMtimeMs`（從 `device_list_dir` 讀，不要抄別的檔案的）；(c) commit 後用 `device_list_dir` 的 `size` 對容器裡的 `wc -c`；(d) 只有 `mtimeMs` 變、`size` 沒變 ⇒ 寫進了舊版 ⇒ 換檔名重來。

**三道檢查，每次都跑**：

| 檢查 | 指令 | 標準 |
| --- | --- | --- |
| 結構 | 裝置上 `python scripts/check-notes.py` | 全站 **0 issue** |
| 編譯與公式 | 容器裡 `node validate.mjs <file>` | 全部通過（兩個已知假警報見 §8） |
| 排版 | `preview-note.mjs` → `shot2.mjs` ＋ **`wide2.mjs`** | katex-error **0**、display 溢出 **0**、**亮暗兩色都自己看過** |

- **`shot2.mjs` 的 `wideEq` 抓不到折疊框（`<Details>`／`<Remark>`／`<Try>`）裡的超寬式子**，那是 2026-09-15 用肉眼抓到的；`wide2.mjs` 補這個洞（往上找第一個有實際寬度的祖先來比）。**兩支都跑，而且截圖一定要看**（底線 3）。
- 容器裡跑不動 `astro build`，mdx 由作者本機 dev server 看。改到樣式（`global.css`、元件）時，用容器的 node ＋ KaTeX 把那一段排成靜態預覽頁、亮暗並排，自己先看過再交出去。

## 1. 敘事骨架

**一篇的骨架**（W3.0 已經是模板）：

```
起點問題（生活化、一句話講完想做什麼）
 → 圖 + 圖說
 → <Ask> 把要回答的問題置中丟出來
 → 把問題翻成數學（名詞一個一個給，中間插 <Remark>）
 → <Question> 課堂提問：學生真的會想到的做法，為什麼行不通
 → 第一種答案（既有方法）＋它的代價（<Details> 收技術細節）
 → 再一個 <Question>：把代價變成下一個想法的入口
 → 互動 demo（看得到剛才那句話）
 → <QuizBlock> ×3–5
 → <Bridge> 指向下一篇
 → ## 參考文獻
```

**一節的骨架**：先講**意圖**（我們想幹什麼）→ 再講**機制**（怎麼做到）→ 最後**長出下一個問題**。

- 每一節的結尾要自然生出下一節的問題：「那問題就變成…」「那接下來的問題就很直接了…」「那接著就得問：…」。
- 不要用「這一步把困難搬了位置」這種迂迴鋪陳。能直接問就直接問（例：「那我們要怎麼學這個 $G$？」）。
- 前後節之間要**明確回指**：後面用到前面的結論時，寫「上一個問題的結論是…」「回頭想想 Q2：…」，不要讓讀者自己接。**跨篇也要回指**（W3.2 開頭就回指 W3.0 的 $L_2$ 塌陷、W3.4 的 Q1 回指「條件容易、邊際困難」）。**但回指要指內容，不要指位置**——「上一節」「下一節」會在併節、搬節時無聲指錯，寫「〈DDPM 的訓練〉推出來的那個 loss」或直接 `<Ref>`。

### 一節的模板：讓解法從問題裡長出來（U2.1）

不要先宣布「接下來介紹 Flow Matching」或先把 objective 寫出來。先讓讀者走到一個**真的需要那個數學物件**的位置，方法與公式才出場：

```
回指上一篇留下的問題
 → 用一個生活情境說清楚我們想完成什麼
 → 問：要做到這件事，缺的是哪些量？
 → 先解端點都知道的簡單版本
 → 寫出 reference path 與它的 velocity
 → 用 demo 讓這條路真的動起來
 → <Question> 揭露生成時其實不知道終點
 → 把讀者放進同一個困境，問他會怎麼做
 → 生活直覺給出下一步（例如「跟著人潮走」）
 → 把這個動作翻成 training pair 與 L2 objective
 → 再揭露同一個輸入可能對到多個 velocity
 → 回指已知的 L2 結論，推出 conditional expectation
 → 最後把公式逐項翻回原本的生活情境
```

這個模板的重點不是一定要用人群，而是下面四件事：

- **先解最容易的版本，再讓它自己露出缺口。** 已知 $(x_0,x_1)$ 時路徑很好畫；真正生成時不知道 $x_1$，才有理由需要只看 $(x,t)$ 的 velocity field。
- **問題要改變讀者手上的資訊。** 好問題不是裝飾性的「想一想」，而是讓「本來可行的方法」在新限制下失效，逼出下一個物件。
- **同一個生活情境一路用到底。** U2.1 裡人群、迷路的人、經過同一個街口的人，分別對到 reference paths、只知道 $(x,t)$ 的生成樣本、以及 conditional set；不要每推一條式子就換一個比喻。
- **舊結論要在剛好能解決眼前衝突時才回來。** 先讓讀者看到「同一個 $(x,t)$ 有很多 reference velocities，但網路只能輸出一個」，再回指 M1.2 的 L2 conditional mean；這時公式是答案，不是插入的知識點。

**一節的模板：從目標倒推（2026-09-08 逐句改 W3.1「定義：一步只加一點點 noise」時定下來的，之後每一節都照這個走）**

不要用「這一節要交代三件事，第一件…」這種規格書寫法。改成先問「**我們希望這個東西替我們做到什麼？**」，讓每一個設計決定都是那個問題的答案：

```
1. 回指上一節的粗方向（一句話）
   → 「但這還只是一個直覺。真正要把它變成…，我們得先反過來問：我們希望它替我們做到什麼？」
2. 講出我們真正想要的那個量（$q(x_t\mid x_0)$），並加一句更高的期望
   （「而且最好不用真的一步一步走，就能直接寫出來」）← 這句同時是下一節的伏筆
3. 生活比方把那個量講成人話
4. 寫出它為什麼難（那個積分）
5. 難處逼出第一個設計 → 為什麼還不夠 → 逼出第二個設計
   每個設計自己一個 `##`，標題直接寫它是什麼（`## 第一個設計：下一步只看現在`）
6. 收束：「我們並不是隨便挑了一個 X，而是從想要的目標一路倒推」
```

配套的兩條：

- **一個 `##` 節不要長到 20 段以上。** W3.1 那一節曾經漲到 27 段（全篇最長，比 quiz 那節還長）而中間沒有任何路標；拆成「定義 7 段 / 第一個設計 14 段 / 第二個設計 12 段」之後才讀得動。**拆的時候升成 `##`，不要用 `###`**——全課 46 篇一個 `###` 都沒有，不要為了一節新增一個層級。
- **`<Ask>` 丟出的問題如果有一部分這一篇不回答，就緊接一句指路**：「這一篇我們馬上就會回答第一個問題，而第二個問題中的『需要知道什麼』要等到 <Ref …/> 和 <Ref …/>，而具體該怎麼做則要到 <Ref …/>。」
  **反過來，`<Ask>` 只問一件事、而且下面 Q1 就回答了的話，不要加這句**——那只是在答案前面多說一句「馬上就回答」。（我一開始把這條寫成「每個 `<Ask>` 都要指路」，稽核跑下去誤報 23 篇；全課只有 7 個 Ask 是多問句，而真正需要指路的只有 W3.1 那一個。）

**課堂提問（`<Question>` + `<Answer>`）的公式**：

1. 題目先給**最直覺、學生真的會想到的做法**（「那用傳統 prediction 的做法不就好了？」「照定義不是要跑 800 次遞迴嗎？」「loss 停在 0.3 是 bug 嗎？」「線性路徑比較直，那粒子會走直線嗎？」「精確跳步每個步數都不輸，那為什麼還要學 τ-leaping？」），再問「這樣會發生什麼事／卡在哪裡／這是 bug 嗎？」。
2. 答案的順序固定：**直覺卡在哪 → 把最佳解／梯度／一個最小例子真的算出來 → 往上一層看出真正的結構 → 給出路（通常兩條）＋ 對後面的伏筆**。
3. `<Answer>` **不要**用課堂視角開場。「課堂上收到的答案通常…」「課堂上收到的候選大致有…」這個舊體例已於 2026-09-07 全站廢除，不要再寫。可以寫「會被想到的回答大致有三類…」。
4. **每篇恰好一個 `<Question>`**。2026-09-14 補完最後八篇（w8-1、w8-2、w8-4、w8-6、w9-1、w9-3、w9-5、w9-6）之後，**DMA W3–W9 全部 46 篇都是 1 個**。新寫的篇要跟上。
5. `<Question id>` 從 **Q1** 開始連號（`id` 會顯示出來）。改寫時如果把 Q3 變成 Q1，記得**全站搜一次有沒有別篇寫「某篇 Q3」**（2026-09-14 抓到五處 `Q2` 死引用：w8-3 ×2、w9-1 ×2、w9-6 ×1，那幾篇根本只有 Q1）。

## 2. 語氣

**要**：帶保留、邊想邊講、和讀者站同一邊。

- 常用句型：「我們會…」「其實就是…」「比較適合理解成…」「值得注意的是…」「麻煩就出現在這裡」「很高興的是…」「那接著就得問…」「會看到的事情是…」。
- hedge 用「通常」「可能」「大多」：「這五萬個點**通常**不會均勻散開」「抽出來的點**大多**會落在合理的區域」。
- **把問題往後推的時候，用「等到⋯再討論」，不要用「留到⋯再處理」。**（2026-09-15，作者原話：「我的語氣會說：這些等到 U1.4 再討論！」）差別在態度：「處理」把那些問題當成待辦事項、當成債；「討論」當成接下來要一起做的事。**而且這是全課唯一一個驚嘆號**——它出現在「先別急，我們等一下就來」這個位置，不是在強調結論。同一類要改的還有「留給」「留待」「之後補上」。
- **好消息與壞消息成對出現時，先給好消息。**（2026-09-13 作者原話：「好消息是 learning objective 有了，壞消息是裡面那個 $q(x_{t-1}\mid x_t)$ 還是不可算」。）而且**壞消息要說到最底層**——不是「算不出來」就停，是「所以這個 loss 我們似乎還是算不出來，**也不知道怎麼求 gradient**」。卡住要卡在讀者真的動不了的那一層。

**不要**：

- 編輯口吻的標題與轉場：「先說清楚：…」「總結一下」「換了一種思路——」。
- 收尾金句：「畫不出來，但數學上是同一件事」這類漂亮但沒有資訊的句子。
- 課堂視角的敘述：「課堂上收到的答案」「少數人會說」「幾乎沒有人主動說」。
- 太 AI 的節奏：連續破折號堆疊、每段都用「而…／然而…／換句話說」開頭、名詞化的抽象句（「表達力鬆綁了」寧可寫「$v_\theta$ 可以是任意網路了」）。
- **同一個連接詞不要連著疊。** W3.1 曾經連著三句「但如果反過來呢？」「但反過來，」「但如果問題變成…」——邏輯都對，唸起來很趕。改法是把其中一個換成「不過」，或直接拿掉。
- **編輯口吻的轉場一律刪掉，不要留。** 這一輪被刪掉的實例：「不過這裡要特別分清楚兩件事。」——它只是在宣告接下來要講兩件事，本身沒有資訊。
- **不要用「N 件事值得…」這種先宣告數量、然後停下來的開場。**（2026-09-12 作者原話：「『兩件事值得看清楚。』不是我會說的話。」）那句話只是在報數，本身沒有資訊。**改法：刪掉它，直接說第一件事**——粗體的 run-in 標題（`**目標是確定的。** …`）自己就會組織段落，不需要先報數。已清掉的七處：`dma-w3-2`、`dma-w8-1`、`dma-w8-2`、`dma-w9-1`、`dma-w9-2`、`ml-l2-3`、`ml-l5-0`。**保留**的是後面直接接冒號、不讓讀者停下來等的寫法：「這裡有一件事值得注意：…」「最後一件事值得說清楚：…」。
- **不要用「值得…」去指示讀者現在該做什麼。**（2026-09-15，作者原話：「我再次叮嚀你：值得看清楚，這不是我會用的詞，請修改 hard rule 來避免」。）「值得看清楚」「值得停一下」「值得停一下看清楚」「值得停下來看」「值得留意」——這是下面那條「不要命令讀者的態度」的**軟性版本**：語氣客氣，但做的事一樣，都是在替讀者決定他此刻該把注意力放哪裡。而且它幾乎都出現在「我覺得這件事重要、卻沒有用結構把它撐起來」的時候。
  - **改法：把那句話直接說出來，或讓它自己成為一段的開頭。** 實例：「兩個期望取的對象不一樣，**值得看清楚**：左邊⋯」→「兩個期望值取的對象不一樣：左邊⋯」；「**值得停一下看清楚**這條等式用了什麼、沒用什麼」→「這條等式用了什麼、沒用什麼，差別很大」；「這裡**值得停一下**：**$\sigma$ 划不划算⋯**」→ 直接留那句粗體。
  - **保留的**：「值得注意的是…」（§2 常用句型裡本來就有）、「值得記下來」，以及**講那個東西本身值不值得**的用法——「這個 toy 值得認真建」「錯誤最多也最值得修」「作業 3 值得做」。判準是**句子在指示讀者的動作，還是在評價那個對象**。
  - **grep 要搜裸的「值得」，不要只搜「值得看／停／留意」。**（2026-09-15 當天就踩到：我在 W3.3 §3 寫的「那就**值得把**「整個分布」正式寫下來」逃過了窄版 grep，因為動詞是「把」。）禁用的那一族動詞開放得很——看、停、留意、把⋯寫下來、問一句——列不完，所以清單只能當提示，判準要靠上面那一條。
  - 這條到 2026-09-15 才被抓到，原因是 §2 的「常用句型」清單裡本來就列著「值得停一下看清楚…」——那是我自己加進去的，已經刪掉。**準則裡的正面清單也會害我犯錯，發現作者退回某個寫法時，記得回頭看它是不是被我寫進了推薦清單。**
- **不要用「免費」去形容我們手上有的東西或某個做法。**（2026-09-12 作者的原話：「不要一直加上『免費』兩個字」。）「forward process **免費**給我們配對」「一個幾乎**免費**的想法」——這是我的口頭禪，不是作者的。改法：說出它到底便宜在哪，或直接不修飾——「讓我們可以**輕易地**製造一堆配對」「一個**不必增加任何新機器**的想法」「除了計算量之外**不必多付什麼**」。
  - **例外：反過來用是可以的。** 「X **不是**免費的」「不是免費午餐」說的是「有代價」，那是相反的修辭動作，也是這些筆記本來就在用的（`ml-l0-1`、`ml-l4-3`、`ml-l5-1`、`math-m2-4`、equivariance 那幾篇，以及一個篇名「對稱性不是免費午餐」）。這些不要動。
  - **這條的一般形式：作者沒用過的口頭禪，我就不要自己長出來。** 同一類的還有「其實」開頭氾濫、以及任何我覺得「講起來很順」但作者的稿子裡從來沒出現過的修飾語。改稿時 grep 一下自己新加的形容詞，看作者的原文裡有沒有那個詞。
- **不要宣稱「唯一」。**（2026-09-13，作者原話：「不要用唯一的取捨吧」。）「這是全篇**唯一**的取捨」「**唯一**會壞的情況」這種寫法要作者替我背書一個全稱命題，而且讀者只要想到一個反例，整段的可信度就掉了。改法：把事實留著、把「唯一」拿掉。**例外**是數學敘述（「反向 rate 裡唯一不知道的量」「兩條合起來唯一決定 $f$」），那是可查證的，不是修辭。
- **不要命令讀者的態度。**（2026-09-13，作者原話：「我通常不會說這種話」。）被刪掉的實例：「**現在不要直接相信上面的結論**，自己推一次。」同族的還有「請務必停下來想一想」「這裡千萬不要跳過」。停頓要靠**結構**（把答案折起來、給一個會答錯的預測），不是靠請求；`<Try>` 的 `summary` 本身就是訊號，前面再加一句訓話只是把它稀釋掉。
- **不要用形狀詞去描述只在一個 toy 上量到的曲線。**（2026-09-14，作者原話：「也不要講甚麼盆地，因為我們沒有理論根據」。）我在 W8 量到多步 CM 的誤差「先降後升」，就寫成「這是一個盆地」——那是從一個 toy 讀出來的形狀，沒有理論撐。**改法：只講站得住的兩句**——(a) 已經證明的（真值 $f$ 在任何步數都精確）、(b) 保證沒了（ODE 有 $O(1/N)$，多步 CM 沒有）。量到的曲線寫在 lab 裡當觀察，不當定律。

**節標題**用問句或動作，不用抽象名詞：

- 好：`## 「生」一張圖片，與「來自同一批資料」`、`## 換一個角度：不學密度，直接學一個能生成樣本的函數？`、`## 其實有無限多個生成方式`、`## 真的要跑 t 次嗎？`、`## 目標寫得出來，可是算不出來`、`## 把一個整體問題切成一堆小任務`、`## 一個很便宜的觀察`、`## 交換一次就看出來了`、`## 把水管倒過來`、`## 消化一下`
- 壞：`## 先說清楚：…`、`## 第一個框架`、`## 定義`、`## 小結`

**標題寫目的，不寫手法。**（2026-09-13 W3.2 連改兩個標題之後定下來的。）

| 原本 | 改成 | 差在哪 |
| --- | --- | --- |
| `## 再算一次 Bayes` | `## 把 $q(x_{t-1}\mid x_t,x_0)$ 算出來` | 前者只講用什麼工具，後者講要拿到什麼 |
| `## 挑一個模型族` | `## DDPM 的訓練` | 「挑模型族」是我的抽象說法；作者的理由是「不是真的改變模型（通常根據資料）」——那個詞在讀者的經驗裡指的是別件事 |

配套三條：

- **標題要接住上一節剛給的東西**，讓骨架自己講故事。W3.2 定稿之後從頭讀下來是：怎麼抽樣？→ 算不出來就用學的 → 訓練時多知道一件事 → 把 $q(x_{t-1}\mid x_t,x_0)$ 算出來 → DDPM 的訓練 → 學完之後，怎麼真的走回去？→ 同一個 reverse step，不一定要學 $x_0$ → 表示上等價，但訓練上不相同 → DDPM 的訓練核心其實就這五行。
- **標題裡可以放 `$…$`**（W3.2 有兩個），不必為了避開數學而改用文字繞。
- **標題不要提前洩底。** 課堂提問剛問完「誰能幫我們？」，下一個 `##` 就不能叫「多給一個 $x_0$，同一個 Bayes 就算得動」——那把答案和結論一次講完，讀者不會停下來想。「只說要做什麼、不說結果」和「講目的不講手法」是同一條的兩面：說目的（拿到什麼）可以，說結果（拿到之後發現什麼）不行。

- **術語的定義要放在「第一次真的卡住」的地方，而且只定義一次。**（2026-09-13，作者原話：「不可算（intractable）這個概念感覺要在更早一點就講出來，並且可以沿用」。）作法三步：
  1. 找到讀者第一次真的被擋下來的那一句，在它後面補一句把詞立起來：「⋯也就是得先知道整個 $p_{\text{data}}$（但很明顯我們不知道）。**這種「式子寫得出來、但實際上算不出來」的東西，以下都叫 不可算（intractable）。**」
  2. 之後**沿用**，用兩到三次就夠。中文本來就靠變化撐節奏，同一個詞在十行裡出現五次會變成鼓點。
  3. **後面的出現處不要再夾注一次英文。** 同一篇裡「不可算（intractable）」只寫一次；第二次之後就只寫「不可算」。

- **加噪之後的邊際一律寫 $p_t$，forward 的條件核一律寫 $q(\cdot\mid\cdot)$。**（2026-09-15，作者原話：「我感覺我們是不是應該統一用 $p_t$，把 U1.2 改成也是用 $p_t$」。）掃過全課：$p_t$ 在 **28 篇**裡當邊際用（W3–W8），而拿 $q(x_t)$ 當邊際的**只有 W3.2 一篇**（Bayes 那一式、兩段正文、一個 $\mathbb E_{q(x_t)}$），已經改掉。分工是**邊際換符號、條件不換**：`q(x_{t-1}\mid x_t)=\frac{q(x_t\mid x_{t-1})\,p_{t-1}(x_{t-1})}{p_t(x_t)}`。這和主要參考（*The Principles of Diffusion Models*）以及 W3.3 自己的定義式 `p_t(x_t)=\int q(x_t\mid x_0)p_{\text{data}}(x_0)dx_0` 都一致。**$p_t$ 的定義點在 W3.2 第一次用 Bayes 卡住的那一句**，W3.3 只回指、不重新命名。
- **不要把兩個條件壓成一個三字的名詞短語。**（2026-09-15，作者原話：「容量夠聽起來很怪，應該是講：理想上，模型夠強、訓練到收斂的話」。）「容量夠」是把 `model capacity` 直譯又砍成三個字，中文讀起來像半句話。**改法：把它展開成一個完整的狀態描述，並在前面補上「理想上」**——因為這整句本來就是一個理想假設，講清楚比省字重要：「所以**理想上，模型夠強、訓練到收斂的話**，⋯」。同一類要小心的還有「表達力夠」「資料夠」這種省略主詞的三字短語。（quiz 的 `<Option>` 裡「網路容量夠大」是完整句子，不在此限。）

## 4. 比喻：直白、生活、先行

**規則：先給生活比喻，再翻成數學，而且比喻裡的每個角色都要對到符號。**

已經用掉、之後要**沿用而不是換掉**的比喻：

| 概念 | 比喻 |
| --- | --- |
| $p_{\text{data}}$ | 一片**地形**：山峰是 mode、山谷幾乎是零；我們看得到點，看不到地形 |
| $\mathcal N(0,I)$ | **隨手可得的原料**（想要多少就抽多少） |

| maximum likelihood | 一個**下注的人**，籌碼總額固定（$\int p_\theta=1$），押在資料出現的位置才拿高分 |

比喻的寫法：

- 比喻要有**一句話的收束**，把它扣回數學：「換句話說，就是讓 $p_\theta$ 的地形越來越像 $p_{\text{data}}$。」
- 比喻裡的量要**明確對到式子**：「他手上的籌碼總額固定——這對應到 $\int p_\theta(x)\,dx=1$」。
- 不要為了漂亮而堆比喻；一段只用一個。

**比喻的手藝（2026-09-08 在 W3.1 連續換掉兩個失敗的比喻之後整理出來的）**：

- **要對到的是「結構」，不只是「感覺」。** 檢查方式：問「這個比喻裡，那個數學性質成立的**理由**和真實情形一樣嗎？」
  - ✗ **下棋**（Markov）：盤面已經是一個充分統計量，過去真的都在盤面上，所以「跟過去無關」聽起來像同義反覆——作者的原話是「其實是作弊已經看到過去」。
  - ✓ **考試分發**（Markov）：Markov 性質來自**規則只讀現在這個狀態**。這正是 diffusion 的理由——$q(x_t\mid x_{t-1})$ 只讀 $x_{t-1}$，因為我們把更新規則定成 $x_t=\sqrt{1-\beta_t}x_{t-1}+\sqrt{\beta_t}\epsilon_t$，$\epsilon_t$ 是新抽的、與過去獨立。
- **比喻的端點要和數學的端點對上。** 講 marginal（「不管中間怎麼走」）時，兩條路線**必須收在同一個終點**，否則沒有東西可以「不管」。W3.1 原本一條收高雄、一條收台東，作者抓出來之後改成兩條都走到屏東。
- **比喻裡的數字要和比喻本身對得上。**（2026-09-13。）作者寫「你能給的答案就是以 $1/4$ 的機率盲猜」，而我當時的比喻是「看監視器猜車牌」——車牌沒有四個候選，那個 $1/4$ 憑空冒出來。換成**視力檢查表上的 E**（開口只有上下左右四個方向）之後，$1/4$ 不用解釋就成立了。**比喻裡出現任何數字，先問它在比喻的世界裡算不算得出來。**
- **比喻有極限就當場說出來**，不要留給讀者踩：「不過『跟過去無關』這句話要小心讀：**不是過去不重要，而是過去該留下的東西都已經濃縮在現在這個狀態裡了**，規則只需要讀它。」
- **符號要落到具體的東西上**，不要停在 $x_1,\dots,x_T$：「台大就是起點 $x_0$；一條路線可以是 $x_1=$ 台中、$x_2=$ 台南、$x_3=$ 高雄、$x_4=$ 屏東。」
- **比喻用過就沿用，不要每次換一個。**
- **每一條「已知的公式」「標準結果」出現時，都要配一個生活畫面。**（2026-09-15，作者原話：「按照我的 Style，這裡就會塞入一個生活化的直觀解釋」。）我原本在 W3.3 §2 寫完 $\arg\min_f\mathbb E\|f(X)-Y\|^2=\mathbb E[Y\mid X]$ 之後，直接接「兩個期望值取的對象不一樣⋯」——那是在解釋**記號**，不是在解釋**為什麼**。作者的做法是先給畫面再回到記號。**判準：這條式子如果讀者只看得懂記號、卻說不出「為什麼是平均而不是別的」，就少了一個比喻。**
  - 好的比喻要順便打掉一個誤解。開店那個例子裡是「不是人最多的那一點」——它預先擋掉 mean／mode 的混淆（§9.5），而那個混淆在 $t$ 大時 $\hat x_0$ 為什麼模糊那裡還會再出現一次。
- **查證**：比喻用到真實世界的制度、數字或事實時要查。「指考上台大、在校成績不影響」在現在的制度下是錯的，只有**分發**那條路線才純看考試分數——所以比喻要限定在「考試分發」。

**數學上的類比（toy example）另有一條規則（2026-09-13）**：作者喜歡用一個國中程度的 toy 去照亮一個高階的結構，但**toy 必須真的算給讀者看**，不能只說「是同一招」。W3.2 的例子是拿「配方」照亮 Theorem 2.2.1：

```
這裡用的雖然是 KL，但和 L2 那種把差距平方起來的距離有類似的性質；以 L2 舉一個 toy example，
寫 ā=(a₁+a₂+a₃)/3，minimizing ⅓[(x−a₁)²+(x−a₂)²+(x−a₃)²] 和 minimizing (x−ā)²
會得到一樣的最佳解 x，因為兩者之差是一個常數——配方出來就看得到：

  ⅓[(x−a₁)²+(x−a₂)²+(x−a₃)²] = (x−ā)² + ⅓[(a₁−ā)²+(a₂−ā)²+(a₃−ā)²]   ← 不含 x
```

四個要點：

1. **常數要寫出來給人看**（作者原話：「可以把差的常數寫出來給大家看」）。只說「差一個常數」，讀者沒有辦法確認。
2. **toy 的形式要和被照亮的那個結構對齊。** 一開始寫的是**加總**，但真正的定理用的是 $\mathbb E_{p(x_0\mid x_t)}$——一個**權重和為 1 的平均**。改成 $\frac13[\cdots]$ 之後兩邊的形狀才真的一樣。
3. **toy 的符號不能和正文的符號撞。** 原本用 $a,b,c$，但 $b$ 在同一篇的配方 `<Try>` 裡是中間量；改成 $a_1,a_2,a_3$。
4. **不要把類比說成等同。** 作者的判斷是「這裡用的**雖然**是 KL⋯但**有類似的**性質」。（真正的關係：兩者都是 Bregman divergence，$\mathbb E_Y[D(Y,\hat y)]$ 的最小值都在 $\hat y=\mathbb E[Y]$；L2 版的常數是變異數，KL 版的常數是條件互資訊 $I(x_0;x_{t-1}\mid x_t)$。）

## 5. 慢慢展開的節奏

- **一段一件事，但不要一句一段。** 同一個推進拍點裡的兩到四句要放在一起；只有換問題、換角色、進入公式或得到結論時才空一行。段落同時在做兩件事時才切，不要靠大量空白製造節奏。
- **每一條式子出現之後，下一句一定用白話說它在幹什麼**——除非那個寫法前面已經講過。要做到兩件事：
  - **把式子的兩邊分別唸成中文**，並且交代新出現的記號怎麼讀。例：$q(x_1,\dots,x_T\mid x_0)$ →「豎線右邊是已經給定的東西：給定起點 $x_0$，走出這一整條路的可能性有多大」。
  - 抽象的式子配一個**生活比方，而且比方裡的每個角色都要對回符號**（§4）。
- **期望值一定要寫清楚是對誰取的。**（2026-09-15。）$\arg\min_f\mathbb E\|f(X)-Y\|^2=\mathbb E[Y\mid X]$ 這種式子，兩個 $\mathbb E$ 取的對象完全不同，讀者不會自己補。作法是在 display 上用 `\underbrace` 標出來，下一段再用文字講一次差別（左邊得到一個**數值**、右邊得到一個隨 $X$ 改變的**函數**）。CJK 放在 `\text{}` 裡沒問題（見 §8）。
- **式子要出現在它被動機化的地方，不要集中在前面當定義區。**
- **符號也一樣，第一次用到之前一格才交代，而且一次講完。**
- 抽象詞先給直覺再給定義：先說「哪裡密、哪裡稀」，才說 distribution。
- **算出來給人看**，不要只說「會失敗」：$x\perp z \Rightarrow G_\theta(z)\equiv\mathbb E[x]$；DDPM 的 loss 下界就是條件變異數；W4.3 用兩組配對把 $u_{1/2}((0,0))=(0,2)$ 真的算出來；W5.4 用一行交換算出 $2(a-b)^\top(A-B)$；W6.5 把 parity toy 的合法率算成 $(1+q)/2$、$q=\frac{L}{N^L}\sum_{k<N}k^{L-1}$，$L=N=8$ 得 78.6%，和 W7.6 量到的 78–79% 對上。**能算死的就別用粗估**——W6.5 原本寫「量出來的 8～10% 不合法率就是它」，真值是 21.4%。
- **一段推導如果讀者做得動，就不要替他做完**——交給 `<Try>`（見 §10-G）。
- 一個「困難」要落到**具體的計算步驟**上，之後的 `<Details>` 才有東西可回答。
- 實作段落用「**會看到的事情是…**」帶出預期現象。lab 篇更好的寫法是「**先寫下你的猜測，再跑出來對**」——不要直接把答案寫在步驟裡，也不要在「預期」裡先講結論（2026-09-14 W8.6 步驟 6 就是這樣改的：從「預期：CM 之後幾乎水平」改成「CM 那條線跟不跟得上 FM 的斜率，就是這一步要看的事」）。

### display 的節拍：什麼時候給整行，什麼時候收回行內（2026-09-13）

「式子可以當節拍用」是對的，但會被我用過頭。作者的訊號是「**這裡展太開了，弄得 compact 一點吧**」。判準：

- **一個 display 要放的是「新的、接下來會被指著看的東西」。** 已經講過的符號、只是把上一句重講一次的式子，收回行內。
- **只有一個符號的 display 幾乎一定是展太開。**
- **連著兩個 display 中間沒有推進，就是多了一個。** 反過來，W3.2 的 `<Try>` 裡有 11 個 display，每一個都推進一步，那不算多。**數量不是問題，「每一個都在往前走」才是判準。**
- **保留的是收束用的 blockquote 匾額**，那不是 display。

### 每一篇都要收口（2026-09-13）

**一篇筆記開頭問的問題，篇內要給出那一行答案。** W3.2 開頭問「倒著走一步，如何從 $q(x_{t-1}\mid x_t)$ 抽樣？」，訓練都推完了卻從來沒有真的走過一步——補上的是一個很短的節〈學完之後，怎麼真的走回去？〉。W3.3 2026-09-15 重排之後也是：開頭問「一個看起來只是做 denoising regression 的網路，到底學到了多少關於 data distribution 的資訊？」，Bridge 第一句就回答「那支只看 pairwise 配對的 regression，學到的是整個 $p_t$ 的 score」。

三條配套：

- **收口的節要短。** 它的工作是把開頭的問題關掉，不是開一個新主題。
- **標題和開頭的標題對稱。**
- **重複一條式子是可以的。** 但要在回報時講出來，讓作者決定。

## 6. 精簡但不失詳細

- 主線只留讀者非看不可的東西；**技術細節、名詞解釋、旁支一律收進可折疊的框**（§7）。
- 重複的兩段砍一邊。作者的訊號是「有一點點冗長」。
- 精簡之後**要補粗體重點**：每段一到兩處，落在**結論**或**關鍵限制**上，不要整段加粗、**不要加在名詞上**。
  - 反例（作者退回過的）：記號清單「$x_0$ 是**路的起點**…$x_t$ 是**加噪 $t$ 步之後的樣子**…」——四處粗體全加在名詞上，互相搶重點。清單就讓它是清單，不要加粗。
  - 作者在 chat 裡貼的段落**通常是純文字、沒有任何 markdown**（§0.5），所以「他沒寫粗體」不等於「他要拿掉粗體」。

```css
  margin:0}
```

置中 ＋ 上下細線。作者選這個樣式的理由要記住：**收束句「本來就有點像是提問，只是馬上就可以算出來」**——所以它和 `<Ask>`（置中加粗、沒有線）長得像不是 bug，差別由**文字本身**承擔（`？` 對 `。`）。分界是**尺度**：`<Ask>` 問的是整篇／整節的大問題，blockquote 放的是**當場就解決得掉**的一句。

用法規則：

- **匾額裡只放粗體的那一句。** 粗體之後再拖一段說明，置中之後會變成兩種字重混排。2026-09-12 清掉了九處這種寫法，拖尾一律移到下一段的內文。句號也要收進粗體裡（`**…是維度。**`，不是 `**…是維度**。`）。
- **內容只有兩種**：本篇**已經證明過的一句結論**，或**下一段就揭曉的預測**。兩者都不是就不該是 blockquote，改成句內粗體。
- 成對的分工可以放兩行，中間用 ` <br />`（前面要有空格，否則粗體收不掉，見 §8）。2026-09-14 的例子：「**forward process 決定我們怎麼製造不同 noise level 的資料；** `<br />` **weighting 決定 training 時多重視哪些 noise level。**」——比原本只說「兩者獨立」多講了各自管什麼。
- **一篇 2–4 次是上限。** 現況 `dma-w3-0`（5）與 `dma-w3-2`（5）超標。
- **匾額太長會折成兩行而且置中對齊，所以要留意行內數學被折斷**（見 §8 的 KaTeX 斷行）。
- 例外：`blockquote.lab-statement`（`HandbookLanding`、`MissionBoard`）不在 `.markdown-body` 裡、有自己的規則。
- **`$$\boxed{...}$$` 是另一件事**：全課 17 個 `\boxed` 都放**中心等式**（W3.1 的 closed form、W3.3 的 Tweedie、W5.0 的通式、W7.1 的 $\dot p_t=p_tR_t$…）。讀者已經學會「框＝這一篇的那條式子」，所以拿它放標語會和那個約定打架——真要放標語，先問是不是該用匾額。

- 需要並列比較兩三個東西時用**小表格**（三到四列、兩三欄）比連續散文有效：W4.2 的「Tweedie vs CFM」、W4.4 的四個軸、W5.1 的 2×2、W5.5 的六個技巧、**W7.2 的 conditional trick 總表**（KL／MSE／速度／通式／比值五列，全課最完整的一張）、W7.5 的 path / target / sampler、W9.5 的四軸總表。

- **CJK 粗體（2026-09-07 用 build 出來的 dist 實測校正過）**：唯一會壞的情況是**收尾 `**` 前面是標點、後面又緊接非標點非空白的字元**，例如 `**密度（density）**記成`、`**ODE（DDIM）**的`、`**…取樣。**<br />`——這時 `**` 不算 right-flanking，粗體收不掉。改法：把標點移出粗體；`<br />` 前面補一個空格。
  **收尾後面直接接漢字沒問題**，**收尾後面接標點也沒問題**。

## 9. 準確性紅線（作者會抓的）

1. **不要把機率性的結果寫成可以控制的規則。** ✗「不是在空白處亂丟一個點」 ✓「我們並沒有一條規則可以直接禁止它落在低密度的地方；只是那些地方本來就比較不容易被抽到」。
2. **不要誇大後面會被推翻的好處。** 只講在後面也成立的話。
3. **density ≠ 機率**：$p_{\text{data}}(x)$ 是「有多密集地出現在 $x$ 附近」；單點機率為 0，值可以大於 1。
4. **EBM 的 maximum likelihood 卡的是 $Z_\theta$ 的梯度，不是它的數值**：$\nabla_\theta\log Z_\theta=\mathbb E_{x'\sim p_\theta}[\nabla_\theta E_\theta(x')]$，要估它就得先從 $p_\theta$ 抽樣。
5. **mode 是密度的局部最大點**，不是「密的那幾團」。
6. **教過的內容不能讓 quiz 選項失效**：教完 normalizing flow 之後，「對 $\log p_\theta$ 做 MLE 需要 $Z_\theta$」就不成立了。
7. score 不是密度學好就順帶得到（在平緩地形上鋪細波紋：海拔幾乎沒變，坡度完全不同）。
8. **$\epsilon$ 是「總噪聲」**，不是任何單一步的 $\epsilon_t$；$\epsilon_\theta$ 收斂到的是 $\mathbb E[\epsilon\mid x_t]$，所以 loss 不會到 0（下界是條件變異數）。
9. **$x_T$ 只是接近 $\mathcal N(0,I)$**，不是等於（prior mismatch）。
10. **「邊際相同」是連續時間、無限步的敘述**；有限步離散化之後 DDPM 與 DDIM 的誤差行為不同。**DDPM vs DDIM 的判準是「模型誤差與離散化誤差誰佔上風」**，不是「步數少時 ODE 勝、步數多時 SDE 勝」——後者已經全課退休（2026-09-14 清掉最後一處，W6.4）。
11. **確定性配對讓我們失去的是「可回歸的 score」，不是「密度」。** $p_t$ **有可能**連密度都沒有（對徑配對），但**不是一定**。
12. **$\gamma_t z$ 對曲率的影響取決於配對**。沒有例外的只有「$\gamma \gt 0$ 讓曲率積分不可能等於 0」。
13. **「線性路徑比較直」成立在條件路徑，不成立在邊際軌跡。**
14. **classifier-free guidance 的 $w=1$ 已經是正確答案**；$w \gt 1$ 生成的是刻意被銳化的分布。
15. **OT 配對的正確敘述是「單調」**。一維的單調等於零交叉，高維只能說「把交叉壓到很少」——實測全域 OT 也還有 0.2–0.8%。
16. **minibatch OT 保邊際**；reflow 則會把上一輪的模型誤差帶進配對。
17. **自我修正需要條件**：足夠大的 $\varepsilon$ 加上足夠的剩餘時間。
18. **高維的距離集中**：$\|x_0-x_1\|^2$ 的相對標準差是 $\sqrt{2/d}$。這是幾何性質，不是實作沒調好。
19. **離散的 $\bar\alpha_t$ 是機率、連續的 $\sqrt{\bar\alpha_t}$ 是振幅**（差一個平方根）。
20. **比值 $p_t(y)/p_t(x)$ 不是機率**。所以 SEDD 的輸出層不能用 softmax。
21. **remasking 保持邊際的條件是「流量」相等，不是 rate 相等**：rate 差一個 $\alpha_t/(1-\alpha_t)$。
22. **remasking 修得動的是「缺 context」的錯，修不動「網路本來就估偏」的錯**。
23. **「精確跳步」精確的是逐位置的邊際，不是 joint**。而它只對「寫得出 $\bar Q_t$」的鏈存在。
24. **離散世界的配對選擇留下的是「對齊」而不是「拉直」**。mask source 下沒有可選的配對方式。
25. **masked diffusion 的「可平行」有一個由資料決定的上限**，不是架構的宣傳詞。
26. **score 的量級是 $O(1/\sigma_t)$**，不是 $O(1/\sigma_t^2)$——由 Tweedie $\nabla\log p_t=-\mathbb E[\epsilon\mid x_t]/\sigma_t$、分子 $O(1)$ 得到。

### B. hedge 比我重一級

作者一貫把斷言弱化，而且弱化的位置都落在「後面某一篇會回頭鬆綁」的地方：

- 「$x_T$ **會**落在 $\mathcal N(0,I)$ 附近」→「$x_T$ **比較容易**落在 $\mathcal N(0,I)$ 附近」
- 「**而** schedule 會讓 $\bar\alpha_T$ 小到幾乎是 0」→「**只要** schedule 讓…」——寫成條件，不是事實
- 「另一端得停在一個我們會抽樣的 **Gaussian** 分布上」→「一個我們**很會抽樣的分布**上（**這裡我們會暫時先用** $\mathcal N(0,I)$）」
- 「固定一個 $x_t$，它**會**被很多張不同的 $x_0$ 造出來」→「它**有可能會**被很多張不同的 $x_0$ 造出來」
- 「這不改變每個 $t$ 對應的最佳 predictor」→「**理想情況下**這不改變…」（2026-09-14）
- 反過來，**要當結論用的地方他會把條件補齊**：只寫「$\bar\alpha_T\to0$ 所以走到 noise」不夠，他加上「**且 $1-\bar\alpha_T$ 會趨近於 1**」。

一句話：**後面會被鬆綁的東西，第一次講就留條件；要拿來當結論的，條件給齊。**

### G. 停頓：讓讀者真的停下來（2026-09-12）

作者的問題：「粗體會不會讓人就直接往下看了？有沒有辦法可以讓大家更容易去思考。」

**唯一真的會讓人停下來的機制只有一個：答案在畫面上看不到。** 其他都是禮貌性的請求。所以分三級，**按「讀者在那一秒鐘產得出什麼」挑**：

| 級 | 形式 | 讀者產得出的東西 | 停得住的機率 |
| --- | --- | --- | --- |
| 1 | blockquote 問句 | 「嗯，好問題」 | 低。成本近乎零，但不要指望它 |
| 2 | **可以答錯的二選一預測** | 是／否 | 中高。沒辦法「大概答一下」，而下一段就告訴他錯了 |
| 3 | **`<Try>`：答案真的折起來** | 一段推導 | 最高。唯一物理上擋得住的 |

- **判準**：產得出是非 → 第 2 級；產得出一段推導 → 第 3 級；只產得出「嗯」→ 第 1 級。
- **三級不互斥。** W3.2 的配方那一節排成**猜 → 做 → 對答案**；那是**同一個停頓**，不算兩個。
- **放在哪裡**：停在「**下一步需要有人想到什麼**」的地方。
- 反例（我自己犯過）：W7.1 原本寫「$\dot p_t=p_tR_t$ 攤開來會長成什麼樣子？」當成第 1 級——問題沒有終點線。那是第 3 級的料，已改成 `<Try>`。
- **不要用「值得停一下」去製造停頓**（見 §2）。那是第 0 級：它只是宣告「這裡重要」，沒有給讀者任何東西可以產出。

**`<Try>` 的三條硬規定**：

1. **問題永遠可見。** `summary` 那一行就是停頓的訊號。
2. **折起來的只能是「過程」，結果一定要出現在下一段的主線上。**
3. **先猜再驗，不要先給答案再叫人推。** 作者把「寫成式子就是」改成「**根據這樣的性質，我們預測會有：**」，後面才接結論，再接 `<Try>`。配套的是 `summary` 也要換成驗證式的問法。

**密度**：推導篇 1–2 個，其他 0–1。

### H. 符號預算（2026-09-13）

作者的原話：「**我覺得這一章節的符號已經太多了，不要再引入多餘的符號。請你參考 The Principles of Diffusion Models 的寫法，盡量用固定那幾個符號就好。**」

**一個單元只有一組符號，由該單元的第一篇建立；後面每一篇都從那一組裡取，不新增。**

五條操作規則：

1. **不要為了式子好看而命名中間量。** 把那個分數原樣寫兩次，比引入一個名字便宜。
   - **這條也管「為了少寫字母而縮寫既有的 schedule 符號」。**（2026-09-15，作者原話：「我覺得保留使用 $\bar\alpha_t$, $\sigma_t$」。）W3.3 的 Tweedie 推導原本開頭寫「為了少寫字母，令 $a=\sqrt{\bar\alpha_t}$、$\sigma=\sigma_t$」，省下的字母不值得讀者在四條式子裡多背一組對照——而且 $\bar\alpha_t,\sigma_t$ 是全課通行的符號，換掉反而讓這一段和前後篇對不上。**判準：縮寫掉的如果是課程已經立起來的符號，一律不縮。**
   - **配套：展開之後式子會變長，太寬的 display 用 `\begin{aligned}` 拆行**（見 §12 的「display 溢出必須是 0」）。
2. **真的需要縮寫時，名字在用到的那一行才出現。** 同一個縮寫在不同篇各自就地定義，不要靠跨篇傳遞。
3. **能直接寫成最終形式，就不要先立一個通用符號再回頭換掉。** 作者的理由是「**這樣後面推導可以省略很多**」。**配套：要直接寫成最終形式，必須先講清楚「為什麼換的是那一塊」。**
4. **$\star$ 這種上標可以用，但要先用文字說它是誰。**
5. **toy example 的字母不要撞到正文的中間量。**

**例外：一個單元裡已經通行的臨時符號可以留。**（作者：「$A,b$ 我覺得無所謂」。）**判準不是「有沒有新符號」，而是「這個符號服務幾行？跨不跨篇一致？」**

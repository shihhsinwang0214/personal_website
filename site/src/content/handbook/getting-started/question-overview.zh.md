> 你可以依照自己現在的進度，找到對應的那一步，用那一頁去幫助自己想出**具體**的研究題目。不用從第一步開始重走。

## 這一區在講什麼

這六個步驟是我自己在找題目時實際會走的流程。它不是「新人專用」——你二年級換方向、或者手上的題目做到一半發現要重新定義問題，都會再走一次。

前面的[我們怎麼做研究](/personal_website/zh/handbook/how-we-do-research)講的是我相信什麼；這一區講的是**怎麼把「我讀了一些論文」變成「我有一個問題」**。這中間的落差是我看過最多學生卡住的地方，而且卡住的時候通常不知道自己卡在哪一步。

```text
Context → Understand → Analyze → Evaluate → Question → Test and Next Step
```

| | 這一步在做什麼 |
|---|---|
| 1. [理解情境](/personal_website/zh/handbook/q1-context) | 搞懂論文在處理什麼問題、什麼場景，先不要急著看方法 |
| 2. [理解現有方法](/personal_website/zh/handbook/q2-existing-methods) | 現有方法怎麼下手、為什麼這樣設計 |
| 3. [分析現有方法](/personal_website/zh/handbook/q3-analyze) | 把讀過的東西整合成一張表，逼出方法之間真正的差別 |
| 4. [評估現有方法](/personal_website/zh/handbook/q4-evaluate) | 它真的解決了嗎？限制在哪？那個限制值不值得解？ |
| 5. [形成你自己的問題](/personal_website/zh/handbook/q5-your-question) | 把 gap 寫成一句具體的問題 |
| 6. [決定下一步](/personal_website/zh/handbook/q6-next-step) | 再讀？做 toy example？先想清楚什麼結果會推翻你 |

## 這不是一條只能往前的流水線

走到第 4 步發現自己其實沒搞懂 problem setting，退回第 1 步是正常的，不是你走錯了。實際上大部分人會在 2 ↔ 3 ↔ 4 之間來回很多次，才生得出第 5 步的那一句話。

我比較擔心的不是你退回去，而是你**沒有意識到自己需要退回去**——例如在第 5 步硬擠出一個問題，但它其實建立在對第 1 步的誤解上。所以每一步我都寫了一個檢核點，讓你可以自己判斷，不用每次都來問我。

## 每一步的檢核點

這些檢核點的共同精神是：**能不能講給別人聽**。我很難直接檢查你腦袋裡的理解，但可以聽你的解釋。而且一個自己其實沒搞懂的東西，講出來的時候通常會露餡——講給別人聽，是我目前知道最便宜也最誠實的檢查方式。

我不是想說講不出來就代表你做得不好，而是希望你把「講不出來」當成一個訊號：那通常代表還有一層沒想清楚，而不是你不夠聰明。

| 步驟 | 大致做到什麼就可以往下走 |
|---|---|
| 1 | 有人問你「你在讀的這兩篇考慮的場景差在哪」，你能講給**任何人**聽 |
| 2 | 你能把某個方法為什麼這樣設計，講給**沒看過這領域文獻的人**聽 |
| 3 | 你的表格上出現至少一個你原本沒預期到的對比 |
| 4 | 你能指出至少一個限制，並且說得出它是作者自己講的、還是你發現的 |
| 5 | 你的問題可以寫成一句話，而且別人讀完知道什麼結果算是回答了它 |
| 6 | 你說得出什麼結果會**支持**、什麼結果會**推翻**你目前的假設 |

## 什麼時候該找我

第 4 步的最後一個問題——**這個限制值不值得解**——請直接來找我討論，不要自己一個人決定。

理由是這個判斷需要的資訊，多半不在論文裡：這個方向社群接下來幾年會不會在意、有沒有人正在做、我們有沒有相對優勢、以你手上的資源做得完嗎。這些是我該提供的東西，不是你該自己猜的。

其他步驟卡住當然也歡迎找我，只是那幾步你自己多半推得動。

## 產物

走完這六步，你手上大概會有：

- 一張比較不同方法的表格；
- 一句寫下來的研究問題；
- 一份「什麼結果會支持／推翻它」的預測；
- 一個最小的下一步。

這四樣東西就是我們第一次認真討論你的題目時，會攤在桌上看的材料。

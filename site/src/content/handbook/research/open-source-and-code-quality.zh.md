> 程式是一種溝通。為下一個讀它的人而寫，那個人常常就是你自己。

## 我們追求的品質

- **可讀勝過炫技。** 清楚的命名、小的函式、明顯的控制流。為讀者最佳化，不是為編譯器。
- **在關鍵處有測試。** 對那些會無聲汙染結果的部分做 sanity check 與測試。
- **足以執行的文件。** 一份 README，能讓人從 clone 走到某個關鍵結果。
- **可重現。** 見[可重現性](/personal_website/zh/handbook/reproducibility)。

研究程式跑得快，這沒問題——但支撐主張的部分值得用心。原型可以鬆散；要發佈的就要加固。

## 釋出程式

我們預設在可以時隨論文釋出程式——它放大影響力，也讓我們保持誠實。釋出前：清理 repo、檢查相依套件授權、移除機密與私密資料、寫一份別人跟得上的 README。釋出的程式掛著實驗室的名字；讓它成為我們自豪的東西。

## 在同一個 codebase 協作

好好用版本控制：小而有意義的 commit、清楚的訊息。友善地互相 code review。讓共用程式比你接手時更好。

> **請編輯：** 補上 repo 慣例、預設授權、與 CI／測試設定。

## 一句話

可讀、關鍵處有測試、可重現、可釋出。寫下一個人能信任的程式——那通常是你，或你論文的讀者。

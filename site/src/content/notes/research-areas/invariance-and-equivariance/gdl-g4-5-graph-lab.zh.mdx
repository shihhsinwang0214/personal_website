# 實作：重編路口與分不開的兩張 graph

<Objectives>

- **執行 graph batch 的共同重編。** 同時變更 adjacency 的 rows、columns 與 node features。
- **分開 node features 與 graph readout。** 用不同 expected tensor 檢查兩種輸出。
- **實際重現不可辨識例子。** 對相同 input features 的 C6 與兩個三角形驗證相同 prediction。

</Objectives>

<Prereq items={["gdl-graph-expressivity"]} />

## 程式裡也要把兩端索引一起換

G5 的 proof 用 $A'=PAP^\top$。在 PyTorch 中，這通常是對 adjacency 的兩個 node axes 使用同一份 index，而不是隻 shuffle features。

這次用小型 undirected graphs 與 scalar node features，target 是所有 node features 的總和。模型有兩層 GCN 與 invariant sum readout；它示範訓練介面與 action，不用這個簡單 target 宣稱已學會 graph topology。

## 同一份 permutation 用三次

```python
from gdl_labs import GCN, defect
import torch

model = GCN(in_dim=2, hidden=24, layers=2)
x = torch.randn(4, 7, 2)
a = torch.zeros(4, 7, 7)
a[:, 0, 1] = a[:, 1, 0] = 1
p = torch.randperm(7)
new_x = x[:, p]
new_a = a[:, p][:, :, p]
print(defect(model(new_x, new_a), model(x, a)))
print(defect(model.features(new_x, new_a), model.features(x, a)[:, p]))
```

Graph output 不變，node features 跟著重排。程式也支援有效 nodes 的 mask；padding nodes 不加入 self-loop，不參與 edge aggregation 或 readout。

這個 dense adjacency 版本適合小圖與教學。大型 sparse graph 應改用 edge-index 的 aggregation，避免配置 $N\times N$ 矩陣；替換計算表示後仍需保持相同 node action。

## 為什麼還要測兩張不同 graph？

```python
from gdl_labs import graph_pair
cycle, triangles = graph_pair()
h = torch.ones(1, 6, 2)
print(defect(model(h, cycle[None]), model(h, triangles[None])))
```

兩張圖不是只重編號就等價，但模型在這組相同 features 下仍給相同答案。這是 <Ref to="gdl-graph-expressivity" /> 的 induction 對應程式結果，不是 symmetry test 失敗。

如果額外加入 degree，兩圖仍 degree $2$，所以也無法補回差別。任意加入 node ID 可能打破初始相同，卻要另外回答是否還符合 node relabeling 的任務要求。

## 作業

先做合法 permutation，再故意只重排 adjacency 的一個 axis，比較差異。請說明後者改了哪一個 node 的連線，而不是隻說「數值變了」。

第二題，給 C6 與兩個三角形不同的 graph labels，在相同初始 features 下訓練。為什麼無法同時精確擬合，卻仍可保持很小的 permutation defect？

加分部分：為可辨識的另一組 graphs 建立 node 或 edge attributes，說明額外資訊從哪裡來，且在重編下怎麼搬動。不要只是把 target 藏進 input。

<Question>

C6 與兩個三角形 prediction 一樣，能否說模型違反了 permutation equivariance？

<Answer>

不能。Equivariance 要求同一份 graph 重編後答案一致，沒有要求所有不同 graphs 都給不同答案。這個結果顯示表示能力的限制。

</Answer>
</Question>

## 四個方向，要逐一檢查，不只看分類分數

G2 的 proof 同時改位置與方向 channel。若實作只把圖片轉了，再比較 pooled scalar，有可能把中間 action 的錯誤藏起來。

因此這次分成兩個測試：先測 $h(u,r)$，再測 global readout。模型使用 lifting、有限 $C_4$ 的方向 correlation，以及同樣的 scalar activation；這是用來檢查 action 的小型 G-CNN，不是完整影像 benchmark。

## 方向 axis 的意義

```python
from gdl_labs import C4CNN, defect
import torch

model = C4CNN(in_channels=1, channels=8)
x = torch.randn(4, 1, 9, 9)
model.eval()
h = model.features(x)  # B,4,C,H,W
q = 1
actual = model.features(torch.rot90(x, q, dims=(-2, -1)))
expected = torch.rot90(torch.roll(h, q, dims=1), q, dims=(-2, -1))
print(defect(actual, expected))
```

方向 shift 用 $q$，因為原方向 $r$ 搬到 $r+q$；讀新 channel 時則來自原 $r-q$，與 <Ref to="gdl-rotation-problem" /> 的推導相同。不要把 forward movement 與 inverse indexing 的正負號混在一起。

程式的 lifting 先把 input 逆旋轉到每個 detector 的視角，套用共同 spatial convolution，再把 feature 轉回原空間。後面沿方向使用相對 offset 的 $1\times1$ mixing，讓下一層也保持 action。

## 為什麼最後 scalar 要用另一種比較？

```python
for q in range(4):
    rotated = torch.rot90(x, q, dims=(-2, -1))
    print(defect(model(rotated), model(x)))
```

`model(x)` 對位置與方向做 global mean，再接 scalar head。因此它應 invariant，expected 不再 rotate 或 shift。訓練 target 使用 input 的平均平方值，本身也對四個旋轉不變。

這個模型為了簡化，用 square input 與不含 stride 的 convolution。$C_4$ 在完整 square 邊界上可以精確重排；一般 rectangular crop 或 arbitrary-angle interpolation 不是同一個測試。

## 作業

先測 $q=0,1,2,3$ 的 feature 與 readout defect。接著故意刪掉 expected 裡的方向 shift，觀察只有位置旋轉為什麼不夠。

第二個修改是讓方向 mixing 使用任意不共享的 $4\times4$ 權重，再測 defect。請指出它違反的是相對方向共享，還是 pooling。

加分部分：改成方向輸出，保留 orientation feature，不要做方向平均。說明 target 應如何隨輸入轉動，以及為什麼 invariant scalar head 不能完成這個任務。

<Question>

四個旋轉後的分類答案相同，就足以證明每個中間 layer 都用正確方向 action 嗎？

<Answer>

不夠。Pooling 可以隱藏部分差異，constant head 也可以讓 scalar 相同。應先直接測中間 feature 的位置旋轉加方向 shift。

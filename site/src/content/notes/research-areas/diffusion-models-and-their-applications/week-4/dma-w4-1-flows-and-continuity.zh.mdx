# 沿著人潮學會怎麼走

<Objectives>
- **給定起始與最終的隨機變數 $X_0,X_1$，寫出一條把兩端接起來的 reference path $I_t$，並求出速度。** 對直線 path $I_t=(1-t)X_0+tX_1$，有 $I_0=X_0$、$I_1=X_1$，而 $\partial_t I_t=X_1-X_0$。
- **把「隨人潮而動」化成可以訓練的 L2 objective。** 抽一組端點與一個時間，以 $I_t$ 為輸入、$\partial_t I_t$ 為 label，讓同一個 velocity field 學會每個位置該怎麼走。
- **說出這個方法學到的最佳 velocity。** 它是所有在時間 $t$ 經過位置 $x$ 的 reference velocities 的 conditional expectation；直覺上，就是迷路的人站在 $x$，觀察此刻可能經過這裡的人，再依可能性平均他們的方向與速度。
- **用 Euler method 實際沿著學到的 velocity field 生成資料。** 每一步在目前位置詢問一次 $v_\theta(x,t)$，再沿著這個方向往前走一小段。
</Objectives>

<Prereq items={frontmatter.prereqs} />

上一篇中，我們有了新的、想解決的問題：**兩個 distribution 之間的搬運**。

我們也聊到可以把它想成：把一堆沙子從一種分布形狀，慢慢搬成另一種形狀。要描述這個搬運，我們需要決定兩件事：**中間怎麼走（path），以及每個地方要往哪裡走（velocity）。**

接下來的問題便是：

<Ask>
<strong>要怎麼找到這條路？<br />
要怎麼知道每一個時刻該往哪裡走？</strong>
</Ask>

## 如果知道起點和終點的話

我們先把沙子換成人群。想像跨年煙火剛結束，人群正從台北 101 周圍散場，大家紛紛走向捷運站：有人去市政府站，有人走向台北 101／世貿站，也有人往象山站。

先想一個比較簡單的情況：假設每個人都知道自己的起點 $x_0$ 與終點 $x_1$。那麼要從起點走到終點，只要選一條在 $t=0$ 從 $x_0$ 出發、在 $t=1$ 抵達 $x_1$ 的曲線，記成

$$
I_t(x_0,x_1).
$$

最簡單暴力的選擇，自然就是橫衝直撞地走直線：

$$
I_t(x_0,x_1)=(1-t)x_0+tx_1,\qquad
\dot I_t(x_0,x_1)=x_1-x_0.
$$

只要給定一組 $(x_0,x_1)$，這條直線給出的位置變化和速度都可以直接算出來，不需要任何神經網路模型。

<Remark label="名稱" summary="端點也隨機之後，這個 construction 就是最簡單的 stochastic interpolant">
固定 $(x_0,x_1)$ 時，$I_t(x_0,x_1)$ 是替這一組端點畫出的 **reference path**。訓練時改成抽隨機端點 $(X_0,X_1)$ 後，$I_t(X_0,X_1)$ 本身也成了 random variable；文獻把這種連接兩端 distributions 的 random process 稱為 **stochastic interpolant**。

這一篇先用 reference path 的說法，專心看單一路線怎麼產生 velocity label；<Ref to="dma-unified-equation" /> 再正式展開 stochastic interpolant 的一般形式。
</Remark>

<Question id="Q1">
**雖然這個方法看起來超讚，但有一個問題藏在裡面。你看得出來嗎？**

<Answer>
對生成模型來說，我們並不知道終點在哪裡；一開始只有起點。想像我們要轉換一張圖片的風格：給定的圖片是起點。如果終點圖片也已經知道了，直接回傳它就好，根本不需要再生成。

真正生成時，我們只會知道：

> **現在是時間 $t$，而我人在位置 $x$。**

我們並不知道自己對應到訓練資料裡的哪一組 $(x_0,x_1)$。所以真正需要的，是一條所有人都能使用的規則：

$$
v_t(x).
$$

可是，站在同一個街口，卻有人往三個不同的捷運站走。**這個 velocity field 到底該聽誰的？**
</Answer>
</Question>

想像你就是那個不知道終點、手機沒電、也沒有地圖的迷路者。站在陌生的街口，你會怎麼做？

## 最自然的方法：隨人潮而動

想像一下，如果我們自己不知道該怎麼走，最自然的方法是什麼？答案很直覺：**跟著人潮走。**

站在時間 $t$、位置 $x$，我們可以看看那些**知道怎麼走的人**——也就是前面已經畫好的 reference paths。看看哪些人的路徑剛好在時間 $t$ 經過這裡，再參考他們當下的方向與速度。

我們也可以讓神經網路做一模一樣的事情。每一條 reference path 都告訴我們：在位置 $I_t$、時間 $t$ 時，應該有一個 reference velocity $\dot I_t$。於是，我們把它當成 label，直接做 regression：

$$
\boxed{
\mathcal L_{\mathrm{CFM}}(\theta)
=
\mathbb E_{t,(X_0,X_1)}
\left[
\left\|v_\theta(I_t,t)-\dot I_t\right\|^2
\right].
}
$$

也就是說，每次看到一條 reference path，$v_\theta$ 都會被要求：**站在 $I_t$ 這個位置時，盡量跟這個人的速度 $\dot I_t$ 一樣。**

但還記得剛才的問題嗎？同一個時間 $t$，可能有很多條 reference paths 都經過同一個位置 $x$。有人往市政府站，有人往 101／世貿站，也有人往象山站；可是 $v_\theta(x,t)$ 只能給出**一個速度**。那它到底該聽誰的？

### L2 自己會完成「從眾」

咦？還記得我們在 **U1** 看過的事情嗎？當一個函數必須同時對很多不同的 target 最小化 L2 距離時，最好的選擇就是：**取平均。**

<Ref to="math-mse-conditional-expectation">M1.2</Ref> 已經證過：固定輸入之後，L2 regression 的最佳解就是 label 的 conditional mean。現在只要把輸入換成 $(I_t,t)$，把 label 換成 $\dot I_t$，就得到

$$
\boxed{
v_t^*(x)
=
\mathbb E\!\left[
\dot I_t(X_0,X_1)
\mid I_t(X_0,X_1)=x
\right].
}
$$

這條式子的意思，其實就是剛才的散場例子：

> **站在 $x$，看看所有可能在時間 $t$ 經過這裡的人，再把他們的方向與速度取平均。**

所以，L2 objective 和 conditional expectation 並不是兩個分開的技巧。**L2 objective 是我們實際拿來訓練的方法；conditional expectation，則是它在理想情況下學到的 velocity field。**

<iframe loading="lazy" src="/personal_website/notes/research_areas/diffusion-models-applications/w4-0-flow-ode.html" class="demo-frame" title="跨年散場：從 reference paths 平均出 velocity" style="height: 820px; width: 100%; border: none;"></iframe>

你可以直接拖動黃色的迷路者，替它指定新的起點 $x(0)$。周圍的方向圓盤把相容的 reference velocities 依方向聚合：扇區越長、越亮，代表那個方向的 posterior signal 越強；黃色箭頭則是它們的 weighted average，也就是 $v_t(x)$。黃線記錄迷路者一路沿著 $v_t$ 走出的 ODE trajectory：實線是已走過的部分，虛線是接下來的路。拖動時，時間會回到 $0$，再從新的起點向前計算整條軌跡；你也可以切換不同的 empirical target samples，看同一條公式如何產生不同的 flow。

這就是 Flow Matching 的核心做法：**先製造容易監督的 reference paths，再讓 regression 把它們整理成一個共同的 velocity field。**

## 訓練完之後，要怎麼真的沿著這個 field 走？

訓練完成後，模型給我們的是：站在任意位置 $x$、時間 $t$，現在應該往哪裡走。要生成資料，我們先從起點 distribution 抽一個 $x^{(0)}\sim p_0$，再解

$$
\frac{\mathrm dx_t}{\mathrm dt}=v_\theta(x_t,t).
$$

一般來說，這條 ODE 沒有 closed-form solution。所以實作時，我們會把 $0$ 到 $1$ 這個區間切成許多小段 $[t_k,t_{k+1}]$，再用 numerical solver 做近似迭代。像是最簡單的 Euler method 會採用

$$
x^{(k+1)}
=
x^{(k)}+\Delta t\,
v_\theta\!\left(x^{(k)},t_k\right).
$$

這條式子其實就很像迷路的人實際採用的做法：**先問一次現在該往哪裡走，沿著這個方向走一小步，再從新的位置重新問一次。** 每一步都要呼叫一次網路；而且就像黎曼積分一樣，通常切得越細，就走得越準，但生成也會越慢。

如果沿途的方向幾乎不變，一大步也可能走得很好；如果 velocity 不斷轉向，就必須頻繁確認方向。我們會在 U3 再回來看看：除了使用更準確的 numerical solver，能不能直接減少這些彎路，讓少步 sampling 也能走得準。

# 沿著人潮學會怎麼走

<Objectives>
- **給定起始與最終的隨機變數 $X_0,X_1$，寫出一條把兩端接起來的 reference path $I_t$，並求出速度。** 對直線 path $I_t=(1-t)X_0+tX_1$，有 $I_0=X_0$、$I_1=X_1$，而 $\partial_t I_t=X_1-X_0$。
- **把「隨人潮而動」化成可以訓練的 L2 objective。** 抽一組端點與一個時間，以 $I_t$ 為輸入、$\partial_t I_t$ 為 label，讓同一個 velocity field 學會每個位置該怎麼走。
- **說出這個方法學到的最佳 velocity。** 它是所有在時間 $t$ 經過位置 $x$ 的 reference velocities 的 conditional expectation；直覺上，就是迷路的人站在 $x$，觀察此刻可能經過這裡的人，再依可能性平均他們的方向與速度。
- **用 Euler method 實際沿著學到的 velocity field 生成資料。** 每一步在目前位置詢問一次 $v_\theta(x,t)$，再沿著這個方向往前走一小段。
</Objectives>

<Prereq items={frontmatter.prereqs} />

上一篇中，我們有了新的、想解決的問題：**兩個 distribution 之間的搬運**。

我們也聊到可以把它想成：把一堆沙子從一種分布形狀，慢慢搬成另一種形狀。要描述這個搬運，我們需要決定兩件事：**中間怎麼走（path），以及每個地方要往哪裡走（velocity）。**

接下來的問題便是：

<Ask>
<strong>要怎麼找到這條路？<br />
要怎麼知道每一個時刻該往哪裡走？</strong>
</Ask>

## 如果知道起點和終點的話

我們先把沙子換成人群。想像跨年煙火剛結束，人群正從台北 101 周圍散場，大家紛紛走向捷運站：有人去市政府站，有人走向台北 101／世貿站，也有人往象山站。

先想一個比較簡單的情況：假設每個人都知道自己的起點 $x_0$ 與終點 $x_1$。那麼要從起點走到終點，只要選一條在 $t=0$ 從 $x_0$ 出發、在 $t=1$ 抵達 $x_1$ 的曲線，記成

$$
I_t(x_0,x_1).
$$

<SlideFigure id="u2-reference-path" src={referenceFigure} slide={18} crop={[35, 150, 1115, 575]} alt="地圖上從藍色起點 x0 到橘色終點 x1 的參考路徑，行人位置標為 I_t(x0,x1)">
圖：先知道起點 $x_0$ 與終點 $x_1$，才能替這一組端點畫出 $I_t(x_0,x_1)$；路線可以彎，也可以直接選直線。
</SlideFigure>

最簡單暴力的選擇，自然就是橫衝直撞地走直線：

$$
I_t(x_0,x_1)=(1-t)x_0+tx_1,\qquad
\dot I_t(x_0,x_1)=x_1-x_0.
$$

只要給定一組 $(x_0,x_1)$，這條直線給出的位置變化和速度都可以直接算出來，不需要任何神經網路模型。

<Remark label="名稱" summary="端點也隨機之後，這個 construction 就是最簡單的 stochastic interpolant">
固定 $(x_0,x_1)$ 時，$I_t(x_0,x_1)$ 是替這一組端點畫出的 **reference path**。訓練時改成抽隨機端點 $(X_0,X_1)$ 後，$I_t(X_0,X_1)$ 本身也成了 random variable；文獻把這種連接兩端 distributions 的 random process 稱為 **stochastic interpolant**。

這一篇先用 reference path 的說法，專心看單一路線怎麼產生 velocity label；<Ref to="dma-unified-equation" /> 再正式展開 stochastic interpolant 的一般形式。
</Remark>

<Question id="Q1">
**雖然這個方法看起來超讚，但有一個問題藏在裡面。你看得出來嗎？**

<Answer>
對生成模型來說，我們並不知道終點在哪裡；一開始只有起點。想像我們要轉換一張圖片的風格：給定的圖片是起點。如果終點圖片也已經知道了，直接回傳它就好，根本不需要再生成。

真正生成時，我們只會知道：

> **現在是時間 $t$，而我人在位置 $x$。**

我們並不知道自己對應到訓練資料裡的哪一組 $(x_0,x_1)$。所以真正需要的，是一條所有人都能使用的規則：

$$
v_t(x).
$$

可是，站在同一個街口，卻有人往三個不同的捷運站走。**這個 velocity field 到底該聽誰的？**
</Answer>
</Question>

想像你就是那個不知道終點、手機沒電、也沒有地圖的迷路者。站在陌生的街口，你會怎麼做？

## 最自然的方法：隨人潮而動

想像一下，如果我們自己不知道該怎麼走，最自然的方法是什麼？答案很直覺：**跟著人潮走。**

站在時間 $t$、位置 $x$，我們可以看看那些**知道怎麼走的人**——也就是前面已經畫好的 reference paths。看看哪些人的路徑剛好在時間 $t$ 經過這裡，再參考他們當下的方向與速度。

我們也可以讓神經網路做一模一樣的事情。每一條 reference path 都告訴我們：在位置 $I_t$、時間 $t$ 時，應該有一個 reference velocity $\dot I_t$。於是，我們把它當成 label，直接做 regression：

<FormulaSteps
  id="cfm-loss"
  compact
  title="怎麼讓模型跟著這個人的速度走？"
  formula={String.raw`
    \begin{gathered}
      \reveal{1}{\mathcal L_{\mathrm{CFM}}(\theta)=} \\[.25em]
      \reveal{5}{\mathbb E_{t,(X_0,X_1)}\big[}
      \reveal{4}{\big\|}
      \reveal{2}{v_\theta}\reveal{1}{(I_t,t)}
      \reveal{3}{-\dot I_t}
      \reveal{4}{\big\|^2}
      \reveal{5}{\big].}
    \end{gathered}
  `}
  steps={[
    { label: '準備輸入', text: String.raw`抽一組端點與時間 $t$，算出位置 $I_t$，得到輸入 $(I_t,t)$。` },
    { label: '模型給出速度', text: String.raw`讓模型在這個位置與時間，給出速度 $v_\theta(I_t,t)$。` },
    { label: '參考速度作為 label', text: String.raw`這個人當下的速度是 $\dot I_t$；拿它當 label，與模型的速度相減。` },
    { label: '衡量平方誤差', text: '把速度差的長度取平方，衡量這一次跟得有多接近。' },
    { label: '對抽樣取平均', text: String.raw`再對不同時間 $t$ 與端點 $(X_0,X_1)$ 的平方誤差取平均，也就是考慮所有我們能產生的 label，參考所有的速度作為學習目標。` },
  ]}
/>

也就是說，每次看到一條 reference path，$v_\theta$ 都會被要求：**站在 $I_t$ 這個位置時，盡量跟這個人的速度 $\dot I_t$ 一樣。**

<SlideFigure id="u2-training-pair" src={trainingFigure} slide={24} crop={[25, 172, 1625, 350]} alt="依序抽出端點、抽出時間 t、算出位置 I_t，再計算該位置的速度 label">
圖：一筆 training pair 的製造流程。直線只用來算出輸入 $(I_t,t)$ 與速度 label $\dot I_t$，不需要先跑一趟 ODE。
</SlideFigure>

每次 training 時，我們只需要抽一組端點與時間 $t$，就能直接算出 $I_t$ 與 $\dot I_t$，不必先解 ODE、真的模擬一條 trajectory，才能製造這組 training pair。Lipman 等人的 Flow Matching 原論文 [1] 把這種訓練方式稱為 **simulation-free training**。

這裡的 simulation-free 只是在說**訓練時不用解 ODE**；模型訓練完成後，要沿著 learned velocity 生成資料，仍然需要 numerical solver。這件事會在〈訓練完之後，要怎麼真的沿著這個 field 走？〉再接著討論。

但還記得剛才的問題嗎？同一個時間 $t$，可能有很多條 reference paths 都經過同一個位置 $x$。有人往市政府站，有人往 101／世貿站，也有人往象山站；可是 $v_\theta(x,t)$ 只能給出**一個速度**。那它到底該聽誰的？

### L2 自己會完成「從眾」

咦？還記得我們在 **U1** 看過的事情嗎？當一個函數必須同時對很多不同的 target 最小化 L2 距離時，最好的選擇就是：**取平均。**

<Ref to="math-mse-conditional-expectation">M1.2</Ref> 已經證過：固定輸入之後，L2 regression 的最佳解就是 label 的 conditional mean。現在只要把輸入換成 $(I_t,t)$，把 label 換成 $\dot I_t$。先把 $I_t(X_0,X_1)$ 簡寫成 $I_t$，照剛才的想法，一部分一部分寫出來：

<FormulaSteps
  id="conditional-velocity"
  compact
  title="站在同一個街口，該聽誰的？"
  formula={String.raw`
    \reveal{1}{v_t^*(x)=}
    \reveal{4}{\mathbb E\big[}
    \reveal{3}{\dot I_t\mid}
    \reveal{2}{I_t=x}
    \reveal{4}{\big]}
  `}
  steps={[
    { label: '現在要選的速度', text: String.raw`在時刻 $t$、位置 $x$，該怎麼選速度？` },
    { label: '同一時刻、同一位置', text: String.raw`先看此刻經過 $x$ 的人：$I_t=x$。` },
    { label: '他們各自的速度', text: String.raw`再看他們各自的方向與速度：$\dot I_t$。` },
    { label: '取條件平均', text: '依這個條件下的可能性，把這些速度取平均。' },
  ]}
/>

這條式子的意思，其實就是剛才的散場例子：

> **站在 $x$，看看所有可能在時間 $t$ 經過這裡的人，再把他們的方向與速度取平均。**

<SlideFigure id="u2-conditional-mean" src={meanFigure} slide={26} crop={[140, 180, 1380, 400]} alt="同一位置的三個橘色參考速度，經 L2 regression 合成一個深藍色平均速度">
圖：固定 $(x,t)$ 後，橘色箭頭表示相容的 reference velocities；深藍色箭頭是依它們的條件機率平均後得到的 $v_t^*(x)$。
</SlideFigure>

所以，L2 objective 和 conditional expectation 並不是兩個分開的技巧。**L2 objective 是我們實際拿來訓練的方法；conditional expectation，則是它在理想情況下學到的 velocity field。**

<iframe loading="lazy" src="/personal_website/notes/research_areas/diffusion-models-applications/w4-0-flow-ode.html" class="demo-frame" title="跨年散場：從 reference paths 平均出 velocity" style="height: 820px; width: 100%; border: none;"></iframe>

你可以直接拖動黃色的迷路者，替它指定新的起點 $x(0)$。周圍的方向圓盤把相容的 reference velocities 依方向聚合：扇區越長、越亮，代表那個方向的 posterior signal 越強；黃色箭頭則是它們的 weighted average，也就是 $v_t(x)$。黃線記錄迷路者一路沿著 $v_t$ 走出的 ODE trajectory：實線是已走過的部分，虛線是接下來的路。拖動時，時間會回到 $0$，再從新的起點向前計算整條軌跡；你也可以切換不同的 empirical target samples，看同一條公式如何產生不同的 flow。

這就是 Lipman 等人提出的 Flow Matching [1] 的核心做法：**先製造容易監督的 reference paths，再讓 regression 把它們整理成一個共同的 velocity field。**

## 訓練完之後，要怎麼真的沿著這個 field 走？

訓練完成後，模型給我們的是：站在任意位置 $x$、時間 $t$，現在應該往哪裡走。要生成資料，我們先在 $t_0=0$ 從起點 distribution 抽一個 $x_{t_0}\sim p_0$，再解

$$
\frac{\mathrm dx_t}{\mathrm dt}=v_\theta(x_t,t).
$$

一般來說，這條 ODE 沒有 closed-form solution。所以實作時，我們會把 $0$ 到 $1$ 這個區間切成許多小段 $[t_k,t_{k+1}]$，再用 numerical solver 做近似迭代。沿用圖中的 notation，這一段用 $x_{t_k}$ 記 sampler 在時間 $t_k$ 算出的近似位置；若使用固定步長 $\Delta t=t_{k+1}-t_k$，最簡單的 Euler method 會採用

$$
x_{t_{k+1}}
=
x_{t_k}+\Delta t\,
v_\theta\!\left(x_{t_k},t_k\right).
$$

<SlideFigure id="u2-euler-queries" src={eulerFigure} slide={28} crop={[30, 775, 765, 125]} alt="Euler 生成時交替詢問目前位置的 velocity，再走一步，並於新位置重新詢問">
圖：在 $x_{t_k}$ 詢問 $v_\theta(x_{t_k},t_k)$，再沿這個 velocity 走 $\Delta t$，得到 $x_{t_{k+1}}$；下一步從新位置重新詢問。
</SlideFigure>

這條式子其實就很像迷路的人實際採用的做法：**先問一次現在該往哪裡走，沿著這個方向走一小步，再從新的位置重新問一次。** 每一步都要呼叫一次網路；而且就像黎曼積分一樣，通常切得越細，就走得越準，但生成也會越慢。

如果沿途的 velocity 幾乎不變，一大步也可能走得很好；如果方向或速度大小不斷改變，就必須頻繁確認。我們會在 U3 再回來看看：除了使用更準確的 numerical solver，能不能直接減少這些變化，讓少步 sampling 也能走得準。

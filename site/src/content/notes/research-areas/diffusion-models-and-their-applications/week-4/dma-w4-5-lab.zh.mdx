# 實作：從 reference path 到 Flow ODE

<Objectives>
- **實作 linear Conditional Flow Matching。** 從一組 $(x_0,x_1)$ 直接製造 $(x_t,t,\dot I_t)$ training data。
- **用 Euler 與 Heun 解 Flow ODE。** 分清模型誤差、trajectory curvature 與 solver error。
- **驗證 Gaussian path 上 noise 與 velocity 的轉換。** 同一個 denoiser 不必重訓，但 path 與時間方向必須對齊。
</Objectives>

<Prereq items={frontmatter.prereqs} />

## 設定：先固定其餘條件

沿用 <Ref to="dma-lab-diffusion" /> 的 two-moons toy、MLP 與 random seed，只改 reference path、training target 與 sampler。這樣最後看到的差異才不會混入網路大小或資料不同。

本單元的符號是：

$$
x_0=\text{起點 noise},\qquad x_1=\text{資料},\qquad t:0\to1.
$$

它和 U1 的 diffusion 時間方向相反，寫程式前先把兩端對一次。

[下載 Week 4：Flow Matching 與 ODE 取樣 notebook（.ipynb）](/personal_website/notes/notebooks/diffusion-models-applications/dma-w4-lab.ipynb)

## 步驟一：製造 reference path

使用 <Ref to="dma-flows-and-continuity" /> 的直線：

$$
x_t=(1-t)x_0+tx_1,\qquad \dot I_t=x_1-x_0.
$$

Training loop 只剩幾行：

```python
for step in range(n_steps):
    x0 = torch.randn(batch, 2)       # 起點
    x1 = sample_data(batch)          # 終點
    t  = torch.rand(batch, 1)
    xt = (1 - t) * x0 + t * x1
    loss = ((model(xt, t) - (x1 - x0)) ** 2).mean()
    loss.backward(); opt.step(); opt.zero_grad()
```

網路看到的是 $(x_t,t)$，label 則是這一組端點的 reference velocity。它不需要知道 density，也沒有先算 posterior weights；L2 regression 會自己完成平均。

你應該會看到 loss 停在大於零的數字。<Ref to="dma-conditional-flow-matching" /> 已經說明原因：同一個 $(x_t,t)$ 可能對應許多不同的 reference velocities，CFM loss 比理想 FM loss 多出的正是 conditional variance。**Loss 不到零，不等於模型沒有學到 optimal velocity。**

## 步驟二：沿著學到的 velocity 走

Euler sampler 是

```python
@torch.no_grad()
def euler_sample(model, x0, n_steps):
    x, h = x0, 1.0 / n_steps
    trajectory = [x]
    for i in range(n_steps):
        t = torch.full((x.shape[0], 1), i * h, device=x.device)
        x = x + h * model(x, t)
        trajectory.append(x)
    return torch.stack(trajectory)
```

先固定一批 $x_0$，分別用 10、50、1000 步生成。檢查兩件事：

1. 步數增加後，終點 distribution 是否逐漸穩定；
2. 圖上的 trajectories 是否等於 training 時畫的直線。

第二題的答案通常是否定的。Training 的直線可以交叉；生成時的 ODE trajectories 跟著 posterior-average velocity，必須繞開那些交叉點。

## 步驟三：量出「彎」的代價

<Ref to="dma-fm-vs-diffusion" /> 的直覺是：隔很久才看一次方向時，急彎最容易走錯。現在固定 exact velocity，把模型誤差拿掉，只比較 solver 與 trajectory。

<iframe loading="lazy" src="/personal_website/notes/research_areas/diffusion-models-applications/w4-5-steps.html" class="demo-frame" title="步數對誤差：斜率與高度" style="height: 830px; width: 100%; border: none;"></iframe>

在 log-log 圖上：

- **斜率**主要反映 solver order：Euler 約為 $-1$，Heun 約為 $-2$；
- **同一斜率下的高度**反映 trajectory 的 error scale，較彎的 path 通常需要更多步。

<Remark label="量測提醒" summary="先把分岔錯誤與離散化誤差分開">
少數粒子可能因為步數不同而走向不同 mode。這種誤差是 $O(1)$，不會隨步長平滑下降，混進平均後會蓋掉 solver order。

因此 notebook 同時畫 median 與 mean：median 用來讀離散化收斂，mean 則保留「走錯 mode」這個真實但不同的問題。
</Remark>

## 步驟四：把 U1 的 denoiser 換成 velocity

載入 U1 在 VP path 上訓練的 $\epsilon_\theta$。依照 <Ref to="dma-linear-path" />：

```python
def eps_to_velocity(eps_model, x, t):
    a, s = vp_alpha(t), vp_sigma(t)
    da, ds = vp_alpha_dot(t), vp_sigma_dot(t)
    eps = eps_model(x, to_ddpm_time(t))
    return (da / a) * x + (ds - da * s / a) * eps
```

用 ODE sampler 積分這個 velocity，再與 deterministic DDIM 比較。時間格越細，兩邊的 trajectories 與終點應越接近；剩下的差異來自離散方式與時間格點，而不是另一個模型。

<Ask>
既然 $\epsilon_\theta$ 能換成 velocity，<br />
能不能順便把 VP path 換成 linear path？
</Ask>

不能。`eps_to_velocity` 裡的 $(a,s,\dot a,\dot s)$ 必須來自模型 training 時看過的 path。換輸出座標不需要重訓，換中間 distribution 則需要。

## 作業

1. **非 Gaussian 起點。** 把 $x_0$ 換成 $[-2,2]^2$ 的 uniform distribution，重新訓練並畫出 trajectories。哪些程式碼不必改？
2. **Coupling。** 保持 $p_0$、$p_1$ 不變，比較 independent pairing 與 minibatch 內依位置配對。畫出 reference paths、ODE trajectories 與少步誤差。
3. **Path。** 固定 pairing，只把 linear path 換成 time-reversed VP path。比較兩者的 marginal trajectories；不要用 conditional paths 的形狀直接猜答案。
4. **Solver。** 對同一個 velocity field 比較 Euler 與 Heun，從 log-log 圖估計斜率。

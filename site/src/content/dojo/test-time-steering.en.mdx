$$
p_\theta(x_0\mid c).
$$

Here $\theta$ denotes the generative model’s parameters. For continuous images, $p_\theta$ is a probability density, not the probability of drawing one exact image. Given “a dog in a red hat,” images matching that description should receive higher density.

**Providing the condition during training so the model learns to generate accordingly is called conditional training.** This does not mean retraining for every new prompt: a model that has learned text inputs may combine descriptions it has never seen together. Our original model, however, lacks that input and needs to acquire this ability first.


Try the operation on a plot first. There are $256$ labelled samples per class. This toy model uses input $c$ to choose a Gaussian mean $\mu_c$; its learnable parameters $(\mu_0,\mu_1)$ both start at zero and the spread stays fixed. Learn the means, then change only $c$ and inspect the plot and parameters.

</Talk>

<Say id="conditional-toy" partner="lumi" label="Train a model that actually reads a class" next="Connect the same operation to diffusion">
Label the left group $c=0$ and the right group $c=1$, with $m=256$ training examples per class. $$

$$

The derivative for $\mu_c$ is $\tfrac12(\mu_c-\bar x_c)$, where $\bar x_c$ is that class's sample mean. <Talk partner="lumi" pose="explain" id="p-conditional-diff" label="Add the description, keep the target?" next="What about velocity prediction?">
> “It was practicing noise prediction. Could we keep that exercise and just let it read the description too?”

Yes. Draw $(x_0,c)$, choose a noise level $t$, and add known noise $\epsilon$ to form $x_t$. The network now sees $x_t,t,c$ and outputs $\epsilon_\theta(x_t,t,c)$. We still compare it with the noise $\epsilon$ actually added.

The prediction error to minimize is therefore

$$
\begin{gathered}
\mathcal L_{\mathrm{diff,cond}}(\theta)\\
=\mathbb E_{x_0,c,t,\epsilon}\Big[\\
\|\epsilon-\epsilon_\theta(x_t,t,c)\|^2\Big].
\end{gathered}
$$

The expectation averages over training images and descriptions, sampled times, and added noise. Squared error measures how far the prediction is from the known noise. Updating $\theta$ with this loss lets the model learn different predictions for different descriptions.

We keep diffusion’s time convention: larger $t$ means more noise, and generation moves toward the clean end at $t=0$. **The new element is the input $c$. The regression target becomes neither text nor a finished image.**
</Talk>

<Talk partner="lumi" pose="explain" id="p-conditional-fm" label="Can velocity prediction read descriptions too?" next="Check whether the target changed">
For Flow Matching, the original target is a reference path’s velocity. Write the noise endpoint as $X_0$ and data endpoint as $X_1$, with condition $c$ attached to the data endpoint. Here time runs from the source at $t=0$ to data at $t=1$, separately from diffusion’s convention above.

For example, choose a straight reference path:

$$
\begin{gathered}
I_t=(1-t)X_0+tX_1,\\
\partial_t I_t=X_1-X_0.
\end{gathered}
$$

Training endpoints are known, so this velocity label can be computed. Give $I_t,t,c$ to the velocity network and compare its prediction $v_\theta(I_t,t,c)$ with the same original target:

$$
\begin{gathered}
\mathcal L_{\mathrm{FM,cond}}(\theta)\\
=\mathbb E_{t,(X_0,X_1,c)}\Big[\\
\|v_\theta(I_t,t,c)-\partial_t I_t\|^2\Big].
\end{gathered}
$$

This expectation averages over sampled endpoints, conditions, and times along the path. During generation, the data endpoint is unknown; we follow the learned velocity step by step. The reference path constructs training examples rather than assigning each generated sample a known endpoint or route in advance.

Lumi makes the same modification for both models: **keep the original regression target and let the network also read $c$.** The condition affects $\theta$ during training. That is conditional training.
</Talk>

<Say id="finetune-toy" partner="mugi" label="Actually update the original mixture's weight" next="Connect this to the diffusion preference objective">
Keep the component means and standard deviation fixed, and learn the original model's mixture weight. Parameter $\theta$ specifies right-mode weight $w_\theta=1/(1+e^{-\theta})$:

$$
p_\theta(x_0)=(1-w_\theta)\mathcal N(x_0;-2,\sigma^2)+w_\theta\mathcal N(x_0;2,\sigma^2).
$$

Originally $\theta=0$, giving equal weights. Collect $512$ preferred examples, initially about $90\%$ from the right group. No $c$ is supplied. Update the same parameter using negative log-likelihood:

$$
\mathcal L_{\mathrm{toy,FT}}(\theta)=-\frac1m\sum_{i=1}^m\log p_\theta(x_0^{(i)}).
$$

The code computes $r_i=w_\theta\mathcal N(x_0^{(i)};2,\sigma^2)/p_\theta(x_0^{(i)})$, the current model's posterior responsibility for the right group. The gradient is $w_\theta-\frac1m\sum_i r_i$. After updating $\theta$, generate from the new $p_\theta$ and inspect whether mass moved toward the preferred data.


Fixing centers and learning only a weight is a choice made for this toy plot. Fine-tuning can also update centers, other network weights, or a full parameter set; the defining operation is continuing to learn from new data in the original model.
</Say>

<Talk partner="mugi" pose="explain" id="p-finetune-loss" label="How do selected photos become practice?" next="Inspect the parameter update">
Write Mugi’s selected preferred data as $\mathcal D_{\mathrm{pref}}$. The original model does not read $c$, so this dataset contains clean images $x_0^{(i)}$ without adding descriptions it cannot use.

Draw $x_0$ from these images, choose $t$, and add $\epsilon$ to form $x_t$. We still compare predicted noise with the noise actually added; only the image source changes:

$$
\begin{gathered}
\mathcal L_{\mathrm{align}}
(\theta;\mathcal D_{\mathrm{pref}})\\
=\mathbb E_{\substack{x_0\sim\mathcal D_{\mathrm{pref}}\\t,\epsilon}}\Big[\\
\|\epsilon-\epsilon_\theta(x_t,t)\|^2\Big].
\end{gathered}
$$

This loss measures noise-prediction error on preferred images, averaging over images drawn from that dataset, times, and noise. The preferred data changes, while the regression exercise stays the same.

For an already conditional model, collect $(x_0,c)$ and also supply $c$ to the prediction. Flow Matching can likewise retain velocity regression and practice on preferred data. In each case, the data distribution used to update the model changes.
</Talk>

<Talk partner="mugi" pose="explain" id="p-finetune-update" label="A late request can still update parameters" next="Differentiate with respect to what?">
With this loss, gradient descent can continue the model’s learning:

$$
\begin{gathered}
\theta\leftarrow\theta\\
-\eta\nabla_\theta
\mathcal L_{\mathrm{align}}
(\theta;\mathcal D_{\mathrm{pref}}).
\end{gathered}
$$

We differentiate with respect to $\theta$ because the learned parameters are what we want to change. The gradient points toward increasing loss, so the minus sign moves toward lower error; the learning rate $\eta$ sets the update size.

Mugi’s request arrives after the original training, but this update still writes it into $\theta$. Tomorrow, even without the image-selection program, we would be using an updated model.

Other alignment methods may use pairwise comparisons or reward weighting. Here we chose a directly computable regression loss on preferred data. **To identify the boundary, check whether the original $\theta$ changed, not just when the request arrived.**
</Talk>

<Say id="steering-toy" partner="nori" label="Write the selection operation explicitly" next="Derive the density from its cumulative distribution">
Each batch independently generated $x_0^{(1)},\ldots,x_0^{(N)}\sim p_{\mathrm{base}}$, then computed

$$
i^*=\arg\max_{i=1,\ldots,N}R(x_0^{(i)}),\qquad x_{\mathrm{return}}=x_0^{(i^*)}.
$$

For $R(x_0)=x_0$, this selects the maximum; $-x_0$ selects the minimum. The code repeats this for $1,000$ batches, returning one per batch. The histogram contains $1,000$ outputs, but the cost is $1,000N$ complete candidates. The original centers, spread, and weight never update.

Why can the returned density differ from the candidate density? Start with the event that a maximum stays below a chosen location.
</Say>

<Say id="steering-density" partner="nori" label="Why does choosing a maximum concentrate on the tail?" next="Inspect helpers and intermediate adjustments">
Let $F(x)=P(X\le x)$ be the base cumulative distribution and $f(x)$ its density. The returned maximum is at most $x$ exactly when all $N$ candidates are at most $x$. Independence gives

$$
P(X_{\max}\le x)=F(x)^N,\qquad f_{\max}(x)=Nf(x)F(x)^{N-1}.
$$

The plot numerically evaluates this density and compares it with actual generated outputs. Increasing $N$ changes the returned distribution and can concentrate it in the tail, which differs from simply drawing from one original component.
</Say>

<Reveal partner="nori" pose="explain" id="best-of-n" label="More candidates change both success and cost" next="Read the route's final reflection">
Independence lets us multiply the miss probabilities. All $N$ candidates miss with probability $(1-p)^N$; at least one hit is the complementary event:

$$
\begin{gathered}
P(\text{at least one hit})\\
=1-(1-p)^N.
\end{gathered}
$$

For $p=0.01$, $10$ candidates give about a $9.6\%$ chance of at least one hit, and $100$ give about $63.4\%$. Even a hundred candidates do not guarantee a hit.

Fix a desired success probability $0<a<1$, with $0<p<1$. We need $(1-p)^N\le 1-a$, hence

$$
N\ge\frac{\log(1-a)}{\log(1-p)}.
$$

For small $p$, $\log(1-p)\approx-p$, so the required $N$ scales like $1/p$. Success becomes more likely at the cost of generating more complete candidates. The helper only scores at the end; it has not redirected nearly successful images along the way.
</Reveal>
